# Бот (bot/)

Отдельный процесс (`python -m bot.main`, long polling, **один экземпляр**). Своих таблиц
нет: базу читает и пишет через слой данных `backend/` (`Database`, `Repository`,
`services`).

| Файл | Что делает |
|---|---|
| `main.py` | Точка входа: Bot, Dispatcher, меню, список команд, циклы напоминаний и рассылок |
| `config.py` | Настройки из `.env` (`BOT_TOKEN`, `TMA_URL`, `LOG_*`) |
| `constants.py` | Тексты приветствия, кнопок, напоминаний, входа; id анимированных эмодзи |
| `emoji.py` | Повтор сообщения без анимированных эмодзи, если Telegram их отклонил |
| `reminders.py` | Напоминания о привычках и «Пора отметить привычки»: раз в минуту, Telegram или push |
| `broadcasts.py` | Рассылки из админ-панели: очередь в базе, отправка пачками |
| `pacing.py` | Общий темп отправки (лимит Bot API) для напоминаний и рассылок |
| `handlers/start.py` | `/start` — приветствие с кнопкой Mini App, запись пользователя |
| `handlers/web_login.py` | `/start login_<код>` — «Войти через Telegram» из веб-приложения; «Не сейчас» под предложением установить приложение |
| `handlers/membership.py` | Блокировка и разблокировка бота пользователем |

Единственная команда — `/start`. В ответ бот присылает приветствие (анимированный
эмодзи 👋 и жирный заголовок, абзац о проекте, жирный призыв) и inline-кнопку
**«Открыть приложение»** с анимированной иконкой ✈️. Слева от поля ввода стоит кнопка меню «Открыть» — там
места меньше, поэтому подпись короче. Других команд нет: всё взаимодействие идёт в
приложении.

## Напоминания

Если у привычки включено напоминание (настраивается в приложении), в заданное время
бот пишет в чат: **«🔔 Пора выполнить «Название привычки»»** и ставит под сообщением
кнопку **«Открыть приложение»** (как под приветствием) — она открывает приложение, где привычку и отмечают
(сама по себе кнопка ничего не делает). На английском — если в приложении выбран
английский. Время — в часовом поясе пользователя из настроек приложения. Напоминание
приходит только в дни, на которые привычка запланирована, и только пока она за этот
день не отмечена. Режим «Отмечать за вчера» на это не влияет: напоминание всегда про
сегодняшний день.

Так же приходит напоминание **«🔔 Пора отметить привычки»** из настроек приложения
(«Напоминать отмечать»): в выбранные дни и время, если на день отметки есть
неотмеченные привычки (`services.due_checkin_reminders`). День отметки — как в
приложении: в режиме «Отмечать за вчера» — вчерашний.

**«Отмечать автоматически»** (экран привычки, `tasks.auto_mark`). Каждую минуту, после
напоминаний, бот сам отмечает такие привычки выполненными (`services.auto_mark_due`):
без напоминания — сразу с началом дня (по поясу пользователя), с напоминанием — сразу
после него. Только в запланированные дни, не у замороженных и не у привычек «несколько
раз в день». День, на который уже есть запись (пользователь отметил или сам снял
отметку), бот не трогает; пропущенная минута не теряет отметку — проверяются все такие
привычки. В ленте профиля это «auto_checkin»; днём отметки для аналитики не считается.

**Push вместо Telegram.** Если у аккаунта есть push-подписка веб-приложения, напоминание
приходит push-уведомлением на его устройства, а не в чат (один канал, без дублей).
Аккаунт только из веб-приложения без push напоминаний не получает. Подписки, которые
push-сервис считает удалёнными (404/410), стираются; если отпали все — напоминание уходит
в Telegram. Ключи — `VAPID_*` в `.env`.

**«Уведомления» в Mini App** (`users.telegram_notifications`, по умолчанию включено).
Выключено — бот не присылает в Telegram напоминания (и как запасной канал после отпавших
подписок тоже) и рассылки; push веб-приложения приходят как прежде. Ответы на команды,
предложение установить приложение, ответ на отзыв и личное сообщение из админ-панели
приходят всегда.

**Предложение установить приложение.** После первой отметки привычки бот один раз
присылает предложение установить веб-приложение (кнопки «Установить» и «Не сейчас»;
`backend/messaging.py`, `users.install_offer_sent_at`).

Раз в минуту бот спрашивает у базы данных, чьё время наступило (`bot/reminders.py`),
поэтому изменения из приложения подхватываются сразу. Бот только читает базу — через
слой данных API (`backend`); ведёт её API. Рассылка идёт параллельно по
пользователям, но в пределах лимитов Bot API (не больше 25 сообщений в секунду всем и
одного в секунду одному чату), и честно: много напоминаний у одного пользователя не
задерживают остальных.

При старте бот регистрирует список команд из одной `/start` («Перезапуск бота») —
при вводе «/» в поле сообщения всплывает подсказка. Список заменяется целиком, так что
команды прежних версий бота из него уходят.

## Рассылки и учёт пользователей

Рассылку пишут в админ-панели приложения, а отправляет бот (`bot/broadcasts.py`): раз
в несколько секунд он берёт рассылку из очереди в базе и отправляет её получателям
пачками — в общем темпе с напоминаниями (`bot/pacing.py`), с учётом прогресса после
каждой пачки, так что перезапуск бота рассылку не прерывает. Фото и видео уже загружены
в Telegram (копия рассылки приходит её автору первой) и отправляются по `file_id`.

Для админ-панели бот отмечает в базе события Telegram: `/start` записывает пользователя
(так видны и те, кто ещё не открывал приложение), а блокировку и разблокировку бота он
узнаёт из обновления `my_chat_member` и из ответа 403 на отправку. Заблокировавшим бота
рассылки не отправляются.

## Анимированные эмодзи

👋 перед заголовком приветствия, 🔔 в начале напоминания и иконка ✈️ на кнопке
«Открыть приложение» — анимированные (custom) эмодзи Telegram. Боту они доступны, пока у
его владельца Telegram Premium. Их id и обычные эмодзи на замену — в
`bot/constants.py` (`WELCOME_EMOJI`, `REMINDER_EMOJI`, `OPEN_APP_EMOJI`). В тексте
эмодзи передаётся сущностью `custom_emoji` (`aiogram.utils.formatting.CustomEmoji`), на
кнопке — полем `icon_custom_emoji_id`. Если Telegram отклонит сообщение с ними
(например, Premium у владельца закончился), бот отправит его ещё раз с обычными эмодзи и
без иконки на кнопке (`bot/emoji.py`) — приветствие и напоминания всё равно дойдут.
Узнать id эмодзи: отправить его боту и посмотреть `entities` сообщения
(`custom_emoji_id`).

## Технологический стек бота

| Компонент | Библиотека |
|---|---|
| Telegram API | `aiogram` 3.x |
| База данных (напоминания, рассылки, учёт пользователей) | `SQLAlchemy` 2.0 (async) + `aiosqlite`, `pytz`, `Babel` (нужен слою данных API) |
| Конфиг | `pydantic-settings` (`.env`) |
| Логи | `loguru` |
| Push-напоминания | `pywebpush` |

## Переменные окружения (из общего `.env`)

| Переменная | Назначение | Обязательна |
|---|---|---|
| `BOT_TOKEN` | Токен бота от @BotFather | да |
| `TMA_URL` | Публичный HTTPS-адрес фронтенда (кнопка Mini App) | да |
| `DATABASE_URL` | Та же база, что у API | нет (SQLite `./streakbot.db`) |
| `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Push-напоминания веб-приложения; пусто — только Telegram | нет |
| `PUBLIC_BASE_URL` | Адрес веб-приложения, который открывает нажатие на push | нет (`TMA_URL`) |
| `LOG_LEVEL`, `LOG_FILE` | Уровень и файл логов | нет (`INFO`, `logs/bot.log`) |

## Запуск

```bash
pip install -r requirements.txt   # зависимости бота (слой данных — из backend/)
python -m bot.main                # из корня репозитория
```

Запускать из корня репозитория — так же, как API: относительный путь SQLite в
`DATABASE_URL` отсчитывается от рабочей директории. Базу данных создаёт и мигрирует
API-сервер (см. [BACKEND.md](BACKEND.md)).
