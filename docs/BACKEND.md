# API-сервер (backend/)

FastAPI-приложение и **слой данных всего проекта**: модели, репозиторий, создание таблиц.
Бот (`bot/`) импортирует этот же слой. Запуск — из корня репозитория:
`python -m backend.main`. Архитектурные решения — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Технологии

FastAPI + uvicorn (async), SQLAlchemy 2.0 (async) + aiosqlite, alembic. Доступ к
данным — только через `Repository`.

## Как работает

- **Владелец данных.** API создаёт недостающие таблицы при старте (`create_all`),
  поэтому локально на SQLite миграции не обязательны. Схема версионируется alembic
  (см. «Миграции»).
- **Авторизация — два способа** (`dependencies.get_principal`):
  - Mini App: `Authorization: tma <initData>`. Подпись `initData` проверяется по
    алгоритму Telegram Web Apps (HMAC-SHA256 с секретом, выведенным из `BOT_TOKEN`) при
    **каждом** запросе, плюс возраст подписи (`TMA_AUTH_TTL_SECONDS`, по умолчанию
    сутки; `0` — отключить);
  - веб-приложение (PWA): `Authorization: Bearer <token>` — сессия из `web_sessions`
    (в базе — хеш токена; `webauth.py`, `accounts.py`). Срок скользящий
    (`WEB_SESSION_TTL_DAYS`), но не дольше года от входа (`SESSION_MAX_AGE`); блокировка
    администратором и «Выйти на всех устройствах» из Mini App завершают все сессии
    аккаунта, из веб-приложения — все, кроме своей.

  Без валидной авторизации — `401`.
- **Регистрация — автоматически.** В Mini App пользователь создаётся при первом запросе
  по данным из `initData`; @username и имя синхронизируются при следующих запросах. В
  веб-приложении первый запуск создаёт гостевой аккаунт (`POST /auth/guest`, id
  отрицательный — не пересекается с id Telegram); вход через Telegram привязывает или
  объединяет аккаунты (`accounts.py`). Отдельного онбординга нет.
- **Единый формат ошибок:** `{"error": {"code": "...", "message": "..."}}` с
  осмысленным HTTP-статусом — в том числе для неизвестного пути (`404 not_found`),
  чужого метода (`405`) и слишком большого тела (`413 payload_too_large`).
- **Транзакция — до ответа.** Сессия БД фиксируется (`commit`) до отправки ответа:
  если запись не удалась, клиент получает ошибку, а не `200` с несохранёнными данными.
- **Лимиты.** Тело запроса — не больше 64 КБ (проверяется до разбора и до
  авторизации). Один пользователь — не больше `TMA_RATE_LIMIT_BURST` запросов подряд
  и `TMA_RATE_LIMIT_PER_SECOND` в секунду, дальше `429 rate_limited` с `Retry-After`.
  Активных привычек у пользователя — не больше 50 (`409 habit_limit`). Идентификаторы в
  пути и курсоры страниц ограничены сверху пределом 64-битной колонки (`MAX_DB_INT`):
  большее число — `422`, а не ошибка драйвера базы.
- **Сжатие.** Ответы больше 1 КБ уходят в gzip (`GZIP_MIN_BYTES`): каталог поясов —
  ~11 КБ вместо 56. Каталог и поиск поясов собираются при старте API, первый запрос их
  не ждёт.
- **Ответы не кешируются** (`Cache-Control: no-store`, `X-Content-Type-Options:
  nosniff`): это данные конкретного пользователя.
- **Документация API** (`/docs`, `/redoc`, `/openapi.json`) по умолчанию выключена —
  включается `TMA_DOCS_ENABLED=true` для разработки.
- **Активность.** Запрос пользователя отмечает его последний визит (не чаще раза в
  минуту) и день активности — из них аналитика админ-панели. Первый запрос — первое
  открытие приложения.
- **Блокировка.** Заблокированному администратором пользователю API отвечает
  `403 user_blocked`; напоминания и рассылки ему не приходят.
- **Админ-панель.** Каждый `/admin/*` проверяет, что запрос подписан Telegram (Mini App,
  `initData`) и пользователь — в таблице администраторов (иначе `403 admin_required`).
  Сессия веб-приложения прав администратора не даёт, даже у аккаунта администратора: она
  живёт долго и хранится в браузере. `is_admin` в настройках — тоже только в Mini App. Первый администратор — 6422071424
  (`SEED_ADMIN_IDS`), дальше список ведут в самой панели. Путь создания рассылки
  принимает тело до 50 МБ (видео), остальные — до 64 КБ.
- **Логи** — в stderr (и в файл `TMA_LOG_FILE`, если задан); трейсбэки — без значений
  переменных, чтобы в лог не попадали токен бота и initData. Запросы дольше секунды
  пишутся предупреждением (путь без строки запроса). Журнала доступа uvicorn нет — его
  ведёт nginx (без строки запроса, см. DEPLOYMENT.md §7). При старте на публичном адресе
  API предупреждает о небезопасных настройках (`config.production_warnings`: нет
  `WEB_AUTH_SECRET`, CORS `*`).
- **Без входа** (`/auth/guest`, `/auth/handoff/redeem`, `/events`) запросы ограничены по
  адресу клиента — последнему адресу `X-Forwarded-For`, который дописал nginx (`client_ip`).
- **Push** уходит только на адреса push-сервисов браузеров (`webpush.is_push_endpoint`):
  Google, Mozilla, Apple, Microsoft — сразу, другой сервис — если его имя указывает только
  на публичные адреса; IP вместо имени, чужой порт и редиректы не принимаются. Адрес,
  придуманный клиентом (сервер внутри сети), не вызывается никогда.

## Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/sync` | Изменения, сделанные на устройстве, пачкой (`{"ops": [...]}`, до 200; пустая — просто загрузка): `mark` — `{"task", "date", "done", "count"?}` отметить или снять отметку за день (у привычки «несколько раз в день» `count` — сколько раз выполнена за день, `done` сервер считает сам: `count >= times_per_day`; не позже дня отметки и в пределах истории, иначе `invalid_date`; любой такой день — и прошлый, из окна дня в календаре; в незапланированный день, замороженный или сверх цели «Гибкого графика» — бонусная отметка: в `history` есть, в сериях, `total_done` и `period_done` — нет, `services.counted_days`); `note` — `{"task", "date", "text"}` заметка к дню (даты — как у `mark`; до 500 символов после очистки, иначе `invalid_note`; пустая — удалить); `freeze` — `{"task", "date", "frozen"}` заморозить привычку с дня `date` или разморозить (`date` — уже обычный день; даты — как у `mark`; повтор ничего не меняет); `create` — `{"ref", "habit"}` создать привычку, `ref` — её id на устройстве (повтор с тем же `ref` возвращает ту же привычку); `update` — `{"task", "habit"}`; `delete` — `{"task"}` (уже удалённая — не ошибка); `settings` — `{"patch"}` как `PUT /settings`; папки: `folder_create` — `{"ref", "folder": {"name", "habits", "types"?, "kind"?}}` (`types` — типы привычек `group` / `personal` / `frozen` / `unscheduled`: все привычки типа в папке, и новые тоже — считает устройство; `kind` — рекомендуемая папка `unfinished` / `today`: наполняется на устройстве сама, `habits` не читаются и вид потом не меняется; последней; до 10 папок — `409 folder_limit`, название до 24 символов — `invalid_folder_name`), `folder_update` — `{"key", "folder"}`, `folder_delete` — `{"key"}` (уже удалённая — не ошибка), `folder_order` — `{"order": [key | null]}` (`null` — место «Все привычки»). `task` — id привычки или `ref` созданной устройством, `key` — id папки или её `ref`; удалённые привычки в папке пропускаются. Операции применяются по порядку, каждая отдельно. Ответ — `{"results": [{"ok", "id", "error"}], "habits", "settings", "folders": [{"id", "name", "habits", "types", "kind"}], "all_habits_position", "today"}`: итог каждой операции (у отвергнутой — код ошибки, как у одиночного эндпоинта), привычки и настройки после всех операций и день отметки. Так работает приложение; эндпоинты ниже остались для совместимости. |
| `GET` | `/tasks` | `{"habits": [...]}` — активные привычки с историей выполнения за последние 364 дня и статистикой серий. |
| `POST` | `/tasks` | Создать привычку: название, частота (`daily` / `specific_days` + дни недели / `every_other_day` + `start_date` / `monthly` + `start_date` / `flexible` + `period` (`week` / `month` / `year`) и `period_times` — «Гибкий график», N дней за период в любые дни: неделя 1–7, месяц 1–31, год 1–366, иначе `invalid_period` / `invalid_period_times`), напоминания (`reminder_times`: `["09:00", "13:00"]`, до 10, пустой — без напоминания; старые клиенты присылают одно `reminder_time`) и цвет. Ответ — `{"habit": {...}}`. Названия могут повторяться; больше 50 привычек — `409 habit_limit`. Управляющие символы в названии заменяются пробелом. |
| `PUT` | `/tasks/{task_id}` | Изменить привычку — те же поля, что при создании. История отметок сохраняется, серии пересчитываются по новому расписанию. Ответ — обновлённая привычка; нет такой активной привычки — `404`. |
| `DELETE` | `/tasks/{task_id}` | Удалить привычку (мягко: `is_active = false`, история остаётся в базе, название снова свободно). Ответ `204`; нет такой активной привычки — `404`. |
| `POST` | `/tasks/{task_id}/toggle` | Отметить / снять отметку выполнения за сегодня. Возвращает обновлённую привычку. |
| `GET` | `/settings` | Текущие настройки: часовой пояс (с подписью на языке пользователя), язык (`ru` / `en`), тема (`light` / `dark` / `system`), «Отмечать за вчера», «Вид серий» (`grid_layout`), напоминание «Пора отметить привычки» (`checkin_reminder_time`, `checkin_reminder_days`), «Уведомления» в Mini App (`telegram_notifications`), «Переключение свайпом» (`folder_swipe`), `is_admin`. |
| `PUT` | `/settings` | Изменить настройки — передаются только меняемые поля: `{"timezone_city": 498817}` (пояс городом из справочника — `city_id` из `/meta/timezones`), `{"timezone": "Europe/Moscow"}` (или `"UTC+3"`; пояс без города), `{"language": "en"}`, `{"theme": "system"}`, `{"mark_yesterday": true}`, `{"grid_layout": "fixed"}` («Вид серий»: `rolling`, `fixed`, `calendar`), `{"checkin_reminder": {"time": "21:00", "days": ["mon", "fri"]}}` (`time: null` — выключить), `{"telegram_notifications": false}`, `{"folder_swipe": true}`. |
| `GET` | `/meta` | Справочные данные формы привычки: лимит длины названия. |
| `GET` | `/meta/timezones?language=ru` | Каталог часовых поясов для выбора в настройках — по поясу на зону, с запада на восток: зона IANA, город (`city_id` в справочнике, если он там есть), страна (на языке `language`) и текущее смещение. |
| `GET` | `/meta/timezones?language=ru&q=питер` | Поиск города (до 50): по названию на любом языке латиницей или кириллицей, с уточнением страны или региона (`портленд орегон`); по названию страны — ещё и её пояса; по смещению (`+3`) — пояса с ним. У одноимённых городов страны есть `region`. |
| `GET` | `/reviews` | История своих отзывов с последним ответом администратора (`{"reviews": [{id, text, created_at, reply_text, replied_at}]}`), новые сначала. |
| `POST` | `/reviews` | Отзыв из настроек (`{"text": "…"}`, до 2000 символов, не больше 5 за сутки — иначе `429 review_limit`). Появляется в админ-панели; в ответе — отзыв в форме истории. |
| `GET` | `/health` | Проверка живости сервиса и доступности БД: `200 {"status": "ok"}` или `503 database_unavailable`. Без авторизации. |

`GET /settings` возвращает и `is_admin` — по нему в настройках виден вход в
админ-панель.

Совместные привычки — `routers/groups.py` (`backend/groups.py`; только аккаунты с
Telegram, гостю веб-приложения — `403 group_needs_telegram`). Групповой делают и новую, и
уже существующую привычку: `"shared": true` в `create` или `update` в `/sync` (владелец —
пользователь, автоотметка выключается; прошлое — по его отметкам). `"shared": false` в
`update` делает её снова обычной — только пока в ней никого, кроме него (иначе
`409 group_has_members`): группа удаляется, ссылка больше не действует; не передано — как
была. Вступают по ссылке через бота
(`/start join_<код>`, bot/handlers/group_invite.py); состояние после действия приложение
берёт из следующего `POST /sync` — у совместной привычки в нём поле `group` (участники, кто
сегодня выполнил свою часть, `others_history`, `open_from`, а по дням — `others_units`,
`people` и `fill_history`: доля дня, сделанная всеми), а `history`, серии и `total_done` —
по дням, выполненным всеми; `done_today`, `today_count` и `history_counts` — своя часть.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/groups/{id}/invite` | Ссылка-приглашение `{"group_id", "invite_url"}` (`t.me/<бот>?start=join_<код>`, постоянная до сброса) — любому участнику. |
| `POST` | `/groups/{id}/reset` | Новая ссылка, прежняя больше не действует (только владелец — иначе `403 group_not_owner`). |
| `POST` | `/groups/{id}/leave` | Выйти: привычка остаётся у него обычной, со всеми отметками, и с группой больше не связана; прошлое группы не меняется (его дни — по снимку `habit_group_marks`). По ссылке вернётся как новичок — с новой привычкой. Ушёл владелец — владелец тот, кто вступил раньше всех; ушёл последний — группа удаляется, ссылка больше не действует. |
| `POST` | `/groups/{id}/kick` | `{"user_id"}` — исключить участника (только владелец; нет такого — `404 group_member_not_found`): для него — как выход, и он в чёрном списке — по ссылке не вступит (`403 group_banned`, бот так и отвечает). Чёрный список владелец видит в `group.banned` (`user_id`, `name`, `photo`; остальным — пустой); фото исключённого ему тоже отдаётся. |
| `POST` | `/groups/{id}/unban` | `{"user_id"}` — убрать из чёрного списка (только владелец; его там нет — `404 group_member_not_found`): по ссылке снова можно вступить — с новой привычкой. |
| `POST` | `/groups/{id}/notify` | `{"on"}` — «Отметки участников». |
| `GET` | `/groups/{id}/members/{user_id}` | Страница участника (любому участнику той же привычки, себя тоже): `{"habit", "day"}` — его привычка по его отметкам, как обычная (`group: null`, сетка, серии и `total_done` — его, без его напоминаний), `day` — его день отметки. Чужим — `404 group_not_found`, нет такого участника — `404 group_member_not_found`. |
| `GET` | `/groups/{id}/members/{user_id}/photo?v=<версия>` | Текущее фото участника из Telegram (JPEG) — только участникам той же привычки (иначе `404`). Версия — `photo` участника в `group.members` (`users.photo_id`, file_unique_id: меняется вместе с фото); совпала — `Cache-Control: private, max-age=31536000, immutable`, иначе — час. Нет фото или Telegram не отдал — `404 photo_not_found`. Картинку API скачивает ботом по `users.photo_file_id` (ссылка на файл содержит токен) и помнит в памяти по версии (`backend/photos.py`). Какое фото сейчас, сверяет бот (bot/profiles.py): при вступлении и раз в 3 часа. |

Изменение привычки (`update` в `/sync`) у совместной: общие поля (всё, кроме напоминаний:
название, описание, расписание, цель, цвет) меняет только владелец — и они меняются у всех участников (с их «сегодня», прошлое —
по прежнему расписанию); у остальных эти поля не меняются; автоотметка выключена.
Удаление групповой привычки (`delete` в `/sync`) — выход и удаление. Вернувшийся по ссылке
получает новую привычку (прежняя, если он её не удалял, остаётся обычной); его прошлые дни
в группе остаются в счёте у остальных. До 12 участников (`409 group_full`), вступление и
возврат — в лимит привычек.

Формат привычки в ответе:

```jsonc
{
  "id": 12,
  "name": "Зарядка",
  // описание (серым под названием); null — без описания. В запросе (create / update)
  // пустая строка — без описания, не передано — при изменении остаётся прежнее
  "description": "10 минут после пробуждения",
  "done_today": true,
  // запланирована ли на сегодня (по частоте/дням недели); false — отметить можно, но
  // отметка бонусная: в сетке есть, в числах нет
  "scheduled_today": true,
  // частота: "daily", "specific_days" + коды дней недели (иначе []) или
  // "every_other_day" — через день, начиная со start_date (иначе null);
  // "monthly" — то же число каждого месяца со start_date (в коротком месяце — последний день);
  // "flexible" — «Гибкий график»: period_times дней за period в любые дни
  "frequency_type": "specific_days",
  "days": ["mon", "wed", "fri"],
  "start_date": null,
  // «Гибкий график» (иначе null / 0): период (неделя с пн, месяц с 1-го, год с 1 января) и
  // цель — в коротком периоде не больше его дней. Пока цель не набрана, привычка
  // scheduled_today; в день, когда набрана, — тоже; дальше до конца периода отметки
  // бонусные (в периоде засчитываются первые дни по порядку). Серии — в периодах;
  // prior_* — по закончившимся (без текущего)
  "period": null,
  "period_times": null,
  "period_done": 0,     // дней выполнено в текущем периоде
  "prior_streak": 0,
  "prior_best": 0,
  // 364 булевых значения, старое → сегодня; true — день выполнен (статус done)
  "history": [false, true, false, /* ... */ true],
  // Серии и total_done — только по засчитанным дням (services.counted_days): выполнен,
  // по расписанию того дня запланирован и не заморожен. Остальные отметки — бонусные:
  // в history есть, серию не продолжают и не рвут
  "current_streak": 5,  // текущая серия, дней
  "best_streak": 21,    // лучшая серия за всё время
  "total_done": 96,     // сколько раз выполнена за всё время (без бонусных)
  // первое (самое раннее) напоминание «ЧЧ:ММ» в поясе пользователя; null — без напоминания
  "reminder_time": "09:00",
  // все напоминания по возрастанию; [] — без напоминания
  "reminder_times": ["09:00", "13:00"],
  // цвет (тема) — ключ палитры: blue, lightblue, teal, green, yellow, orange, red,
  // pink, purple, indigo, brown, graphite — или свой цвет «#rrggbb» (палитра)
  "color": "green",
  // с какого дня заморожена; null — не заморожена
  "frozen_since": null,
  // 364 булевых значения за те же дни, что history; true — день заморозки
  "frozen_history": [false, false, true, /* ... */ false],
  // сколько раз в день нужно выполнить (1 — обычная привычка) и сколько раз
  // выполнена в день отметки; день выполнен, когда набрано times_per_day
  "times_per_day": 3,
  "today_count": 1,
  // сколько раз выполнена в каждый день history (только при times_per_day > 1, иначе
  // []): неполный день сетка закрашивает долей цвета; серии считают только done
  "history_counts": [0, 3, 1, /* ... */ 1],
  // день после today — в режиме «Отмечать за вчера» это календарный сегодня (иначе
  // false / 0): выключили режим — приложение сразу видит сегодняшние отметки
  "next_day_done": false,
  "next_day_count": 0,
  // «Автоотметка» (только при times_per_day = 1): бот отмечает привычку сам —
  // без напоминания с началом дня, с напоминаниями сразу после последнего
  "auto_mark": false,
  // за календарный сегодня записи ещё нет (ни отметки, ни снятой): приложение само
  // покажет автоотметку, когда ей пора, не дожидаясь бота
  "auto_mark_ahead": true
}
```

«Сегодня» вычисляется в часовом поясе пользователя (пока пояс не выбран — UTC);
индекс 0 в `history` — самый старый день, последний элемент — сегодня. В режиме
**«Отмечать за вчера»** всё считается от вчерашнего дня: отметка ставится за вчера,
`done_today` и `scheduled_today` — про вчера, история и серии заканчиваются вчера.
Напоминания о привычках этот режим не меняет — они всегда про сегодня (запланирована
ли привычка сегодня и отмечена ли за сегодня). А напоминание «Пора отметить привычки»
— про день отметки: в этом режиме про вчерашний (`services._reminder_day`).

Язык новому пользователю выбирается по языку его Telegram (русский — если Telegram
на русском, иначе английский); на нём же бот присылает напоминания.

Серия — подряд идущие выполненные дни. Её прерывает только пропущенный
запланированный день: у привычек «по дням недели» и «через день» незапланированные
дни серию не рвут. Неотмеченный сегодняшний день текущую серию тоже не прерывает — день ещё не
закончился.

**Заморозка.** Замороженная привычка (`tasks.frozen_since`) сохраняет серию: её пропуски
серию не прерывают (но и не продолжают). Отмечать её нельзя, напоминания о ней не
приходят, и она не считается в напоминании «Пора отметить привычки». Заморозка
начинается с дня отметки; при разморозке её дни уходят в `task_freezes` (первый день,
день разморозки — уже обычный) и остаются видны в `frozen_history`. Разморозка в тот же
день, что и заморозка, дней не оставляет.

открытий приложения из этого предложения стирается источник.

Миграция `0030` — прошлое групповых привычек не пересчитывается: `habit_group_marks`
(снимок вышедшего участника за дни закрытого периода — выполнил, сколько раз, заморожен).
Уже закрытым периодам снимок собирается из отметок и заморозок их привычек. Без неё API
не прочитает совместные привычки.

Миграция `0031` — типы привычек в папке: `folders.habit_types` (JSON-список: `group` —
групповые, `personal` — личные, `frozen` — замороженные, `unscheduled` — не на сегодня;
все привычки типа попадают в папку сами, и новые тоже).
У уже созданных папок — пустой. Без неё API не прочитает папки.

Миграция `0032` — «Гибкий график» (частота `flexible`: N дней за неделю / месяц / год в
любые дни): `tasks.period` (`week` / `month` / `year`) и `tasks.period_times`, те же поля
в `task_schedule_periods`. У остальных привычек — NULL. Без неё API не прочитает привычки.

Миграция `0033` — «Сверх плана»: `tasks.overtime` (по умолчанию false). У привычки
«несколько раз в день» счёт может идти дальше цели, до `OVERTIME_MAX_COUNT` (999 999); без
настройки `/sync` ограничивает счёт целью. Без неё API не прочитает привычки.

Миграция `0034` — заметки к дням (окно дня в календаре): `day_notes` (привычка, день,
текст; одна на день, пустая не хранится). В ответе — `habit.notes` (день → текст) за дни
истории. Без неё API не прочитает привычки.

Миграция `0035` — «Сверх плана» в прежних расписаниях: `task_schedule_periods.overtime`
(уже записанным с целью больше 1 — как сейчас у привычки). Прошлый день отмечается по
цели и «Сверх плана» того дня (`/sync`, `services.goal_on`); в ответе —
`schedule_history[].overtime`. Без неё API не прочитает привычки.

> Перед миграцией сделайте копию базы: `python scripts/backup_db.py` (база в режиме
> WAL — простое копирование файла на работающих процессах может потерять последние
> изменения).

## Переменные окружения (из общего `.env`)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен бота — для проверки подписи `initData` | — (обязательна) |
| `DATABASE_URL` | Строка подключения к БД (async-драйвер) | `sqlite+aiosqlite:///./streakbot.db` |
| `DB_POOL_SIZE`, `DB_MAX_OVERFLOW` | Пул соединений с PostgreSQL (у SQLite не используется) | `10`, `20` |
| `TMA_HOST` | Хост API-сервера (`0.0.0.0` — все интерфейсы, например в Docker) | `127.0.0.1` |
| `TMA_PORT` | Порт API-сервера | `8000` |
| `TMA_ALLOWED_ORIGINS` | Разрешённые источники CORS (через запятую; `*` — любой) | `*` |
| `TMA_AUTH_TTL_SECONDS` | Максимальный возраст `initData` в секундах (`0` — без проверки) | `86400` |
| `TMA_RATE_LIMIT_BURST` | Запросов одного пользователя подряд (`0` — без лимита) | `60` |
| `TMA_RATE_LIMIT_PER_SECOND` | Скорость пополнения лимита, запросов в секунду | `5` |
| `TMA_DOCS_ENABLED` | Документация API `/docs`, `/redoc`, `/openapi.json` | `false` |
| `TMA_LOG_LEVEL` | Уровень логов API | `INFO` |
| `TMA_LOG_FILE` | Файл логов API с ротацией (пусто — только stderr) | — |
| `TMA_URL` | Адрес Mini App — для кнопки под копией рассылки автору | — |
| `PUBLIC_BASE_URL` | Публичный адрес страницы установки и веб-приложения (ссылки установки, push) | `TMA_URL` |
| `PUBLIC_API_PATH` | Путь, под которым фронтенд проксирует API (nginx и Vite) | `/api` |
| `WEB_AUTH_SECRET` | Секрет веб-сессий и одноразовых ссылок; смена разлогинит всех веб-пользователей | из `BOT_TOKEN` |
| `WEB_SESSION_TTL_DAYS` | Срок веб-сессии, дней (каждое использование продлевает) | `180` |
| `HANDOFF_TTL_MINUTES` | Срок ссылки установки из Telegram, минут | `30` |
| `TELEGRAM_BOT_USERNAME` | Имя бота без @ для «Войти через Telegram» | спрашивается у Telegram |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Ключи Web Push (`scripts/generate_vapid_keys.py`); пусто — push выключен | — |
