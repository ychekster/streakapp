# «Подключить ИИ»: Claude, ChatGPT и другие ИИ в Knot

Пользователь подключает свой Claude (сайт, Desktop, телефон) или ChatGPT к Knot и
просит его посмотреть привычки, отметить выполненное, составить задачи. Нейросеть
работает на подписке пользователя: Knot только отвечает на её запросы, своих расходов на
ИИ нет.

Устроено по стандарту **MCP** (Model Context Protocol): у Knot есть MCP-сервер
`https://<домен>/api/mcp`, вход в него по **OAuth 2.1** через Telegram.

## Как подключает пользователь

1. Knot → Настройки → «Подключить ИИ»: адрес и «Скопировать адрес», шаги для Claude и
   ChatGPT, список подключённых ИИ с «Отключить» (`screens/AiConnectScreen.tsx`).
2. В ИИ: добавить свой коннектор и вставить адрес.
3. ИИ открывает страницу Knot `/connect` (`frontend/src/connect/ConnectPage.tsx`): какой ИИ
   просит доступ и что он сможет делать, кнопка «Разрешить». Она открывает бота, бот
   спрашивает «Подключить Claude к вашему Knot?» с кнопкой «Разрешить» и называет сайт,
   куда уйдёт доступ (`bot/handlers/web_login.py`: код входа несёт имя ИИ, его client_id и
   адрес возврата, `oauth.login_client`, `oauth.login_host`). Это нажатие
   и есть согласие: страница сама завершает подключение, второй раз ничего нажимать не надо.
4. Браузер возвращается в ИИ, и тот может работать с Knot. Изменения появляются в Mini App
   и веб-приложении при следующей синхронизации (при открытии приложения). Повторное
   подключение того же ИИ заменяет прежнее, а не добавляет второе.

> **Локальная проверка через trycloudflare не работает:** Cloudflare на бесплатных
> туннелях отвечает 403 на запросы с User-Agent `Claude-User` (так Claude вызывает
> `/mcp`), при этом вход и токены проходят. Claude пишет «вы вошли, но сервис отклонил
> запрос». Нужен туннель без блокировки ИИ-ботов или сервер; прод (nginx без Cloudflare)
> отвечает Claude нормально.

## Поток OAuth (backend/oauth.py, routers/oauth.py)

```
ИИ ──GET /.well-known/oauth-protected-resource──▶ где сервер авторизации
ИИ ──GET /.well-known/oauth-authorization-server─▶ эндпоинты
ИИ ──POST /oauth/register───────────────────────▶ client_id (публичный, без секрета)
браузер ──GET /oauth/authorize?…&code_challenge──▶ 302 /connect?… (фронтенд)
/connect ──POST /oauth/login/start, /poll────────▶ вход через бота → тикет (15 мин)
/connect ──POST /oauth/approve───────────────────▶ подключение + код (5 мин) → редирект в ИИ
ИИ ──POST /oauth/token (code + code_verifier)────▶ access (1 ч) + refresh (90 дней)
ИИ ──POST /mcp, Authorization: Bearer <access>──▶ инструменты
```

- PKCE S256 обязателен, код и тикет одноразовые, refresh одноразовый (ротация).
- В базе только хэши токенов и кодов (`hash_token`, как у сессий веб-приложения).
- Таблицы: `oauth_clients`, `ai_connections` (миграция 0051); коды — `auth_codes` с
  видами `oauth_code`, `oauth_consent`, `ai_admin`.
- «Отключить» удаляет подключение, и оба токена сразу перестают работать. Блокировка
  пользователя администратором и удаление аккаунта удаляют и подключения.
- Страница разрешения и бот показывают, куда вернёт браузер (`redirect_host`, `host`):
  приложение с чужим названием «Claude» не спрячет свой адрес.
- Тикет согласия привязан к ИИ, которого назвал бот (`client_id` в коде входа и тикете):
  `/oauth/approve` с другим client_id отвечает `410 login_expired`.
- Вход только в существующий аккаунт Knot (`404 no_account`): гостевых аккаунтов
  страница не создаёт.

## MCP-сервер (backend/mcp.py, routers/mcp.py)

Своя реализация stateless-части Streamable HTTP: одно JSON-RPC сообщение на POST, ответ
обычным JSON, без SSE и сессий. Методы: `initialize`, `ping`, `tools/list`, `tools/call`;
уведомления — `202`. Версии протокола: 2025-11-25, 2025-06-18, 2025-03-26.

Инструмент — функция с аргументами-моделью pydantic (из неё JSON Schema для ИИ и
проверка вызова) и JSON-результатом (`structuredContent` и он же текстом). Ошибка, которую
человек может исправить (нет такой привычки, лимит), приходит результатом с `isError`.

## Что может ИИ (backend/ai_tools.py)

Чтение — по тем же данным, что получает приложение (`list_habits`, `list_todos`…),
изменения — только через `services.apply_sync` теми же операциями, что шлёт приложение.

| Инструмент | Что делает |
|---|---|
| `get_today` | Сегодня: привычки на сегодня (статус, серии), остальные, задачи на сегодня и просроченные |
| `list_habits` | Привычки: id, расписание, цель, статус дня, серии |
| `get_habit_history` | Отметки привычки по дням за N дней, счёт, заморозка, заметки |
| `list_todos` | Списки и задачи |
| `mark_habit` | Отметить или снять отметку за сегодня или прошлый день (`count` для целей больше 1) |
| `add_day_note` | Заметка к дню привычки |
| `create_habit` | Новая привычка |
| `create_todos` | До 50 задач за раз, в список, с днём и напоминанием |
| `update_todo` | Выполнить, вернуть, переименовать, перенести, день и напоминание |
| `delete_todo` | Удалить задачу |
| `create_todo_list` | Новый список задач |

Не может: удалять привычки и списки, менять настройки, приглашать в совместные
привычки, импортировать. Каждое изменение пишется в журнал действий пользователя
(`activity_log`, вид `ai`), подключение и отключение тоже.

## Администратор: статистика (backend/ai_admin_tools.py)

**Сейчас выключено в интерфейсе:** страница разрешения всегда шлёт `admin: false`,
переключателя нет, чтобы не путать обычных людей. Бэкенд готов, включить можно позже.

Раньше на странице разрешения администратор видел переключатель «Статистика приложения». Если
включить, после «Разрешить» бот спрашивает «Разрешить» доступ к статистике
(`messaging.send_ai_admin_request`, `bot/handlers/ai_admin.py`). Админские инструменты
видны ИИ сразу, а работают только после нажатия в боте (`ai_connections.admin_trusted_at`),
и при каждом вызове проверяется, что человек всё ещё администратор.

| Инструмент | Что делает |
|---|---|
| `admin_overview` | «Обзор» админ-панели: новые, живые, активные, Telegram и веб, 30 дней по дням |
| `admin_report` | Раздел аналитики за период: summary, funnel, retention, churn, habits, sources, messaging |
| `admin_journey` | Путь посетителей с сайта по шагам |
| `admin_feature_usage` | Сколько людей пользуются каждой функцией: задачи, списки, папки, таймер, гибкий график, совместные привычки, архив, заметки, push, ИИ |

Только агрегаты, как в админ-панели (без администраторов и тестовых аккаунтов): без
имён, профилей и любых изменений.

## Проверка локально

1. `venv/Scripts/python.exe -m alembic upgrade head`, перезапустить API и бота, `npm run
   build` и preview.
2. MCP Inspector: `npx @modelcontextprotocol/inspector`, транспорт Streamable HTTP,
   адрес `<туннель>/api/mcp`, пройти OAuth и вызвать инструменты.
3. В claude.ai: Настройки → Коннекторы → добавить свой коннектор с адресом туннеля, войти
   через тестового бота.

На сервере нужен `location /.well-known/oauth-` в nginx (docs/DEPLOYMENT.md).
