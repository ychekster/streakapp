# Фронтенд (frontend/)

Одна сборка — три способа открыть (`src/main.tsx`):

- **в Telegram** — Mini App (авторизация `initData`);
- **с иконки на рабочем столе** (`platform.isInstalled`) — веб-приложение (PWA):
  гостевой аккаунт при первом запуске, вход через Telegram, push-напоминания
  (`src/web/`); service worker — `src/sw.ts`;
- **во всём остальном** (вкладка браузера, Threads, десктоп) — страница установки
  (`src/landing/`, адреса `/`, `/install`).

Mini App и веб-приложение — одно приложение, две равноправные версии. Любая правка по
умолчанию вносится в обе, и визуально они совпадают пиксель в пиксель. Только если явно
оговорено «только в веб-приложении» или «только в Telegram», меняется одна версия, а
другая не затрагивается. Где запущено приложение, определяет только `platform.ts` (`appPlatform()` /
`usePlatform()`), компоненты сами `window.Telegram` не проверяют.

## Структура `src/`

```
src/
├── main.tsx, App.tsx      # точка входа (выбор режима) и каркас приложения: вкладки, стопка экранов
├── screens/              # экраны приложения: привычки, привычка, форма, настройки, пояс, отзыв…
├── components/           # общие компоненты (ListItem, Section, Screen, TabBar, YearGrid…)
├── data/                 # привычки и настройки на устройстве: очередь изменений и синхронизация (store.ts),
│                         #   расчёт того, что видно на экране (derive.ts), даты дня отметки (dates.ts)
├── hooks/                # хуки данных и Telegram-кнопок (useHabits, useSettings, useMainButton…)
├── api/                  # HTTP-клиент (client.ts) и запросы по разделам API, в т.ч. admin.ts
├── types/                # TypeScript-типы — зеркало схем backend/schemas.py
├── admin/                # админ-панель: AdminApp, свои экраны, компоненты (графики, фильтры), тексты
├── web/                  # только веб-приложение: сессия, вход, push, аналитика воронки, оформление
├── landing/              # страница установки (config.ts — тексты шагов, видео, встроенные браузеры)
├── telegram/webapp.ts    # обёртка над window.Telegram.WebApp
├── styles/               # дизайн-токены (variables.css) и глобальные стили
├── strings.ts            # все тексты приложения (ru/en); тексты админ-панели — admin/adminStrings.ts
├── preferences.ts        # язык и тема: контекст, системная тема, запоминание на устройстве
├── platform.ts           # где запущено: telegram / web, установлено ли, устройство
├── constants.ts, theme.ts, errors.ts, legal.ts, pressFeedback.ts
└── sw.ts                 # service worker веб-приложения (отдельный tsconfig.sw.json)
```

## Технологии

React + TypeScript + Vite, стилизация — **CSS Modules** + CSS-переменные
(дизайн-токены). Никаких UI-китов и компонентных библиотек — только нативный
браузерный рендеринг.

## Поведение

- При открытии вызывает `WebApp.ready()` и `WebApp.expand()`, а на телефонах (и iPhone,
  и Android) — ещё `disableVerticalSwipes()` и `requestFullscreen()`: приложение
  раскрывается во весь экран и не закрывается случайным свайпом вниз. Фон/шапка
  красятся под дизайн-токен фона. На десктопе и в вебе — только `expand()`.
- Авторизация — автоматически: в Telegram — `initData` из `window.Telegram.WebApp`,
  в веб-приложении — токен сессии (`web/session.ts`); он уходит в заголовке каждого
  запроса (`api/client.ts`).
- Скелетон загрузки и ошибка загрузки бывают только при самом первом запуске, пока на
  устройстве ещё нет данных (см. «Данные на устройстве»); пустой список и запуск вне
  Telegram отображаются понятными сообщениями. Запрос, на который сервер не ответил за
  15 секунд, считается ошибкой сети — экран не зависает в загрузке.
- Такое сообщение по центру экрана (`StatusMessage`) устроено одинаково везде: серый
  круглый значок, под ним жирный заголовок и подпись почти того же размера вплотную к
  нему. Значки — свои SVG (`StatusIcons`), а не эмодзи: галочка на пустом списке,
  восклицательный знак на ошибке, звезда после отправленного отзыва, самолётик вне
  Telegram, вращающееся кольцо на загрузке. Размеры — в дизайн-токенах `--status-*` и
  `--font-size-status-*`.
- Ошибка отрисовки не оставляет пустой экран: `ErrorBoundary` показывает сообщение и
  кнопку перезапуска.
- Отметка выполнения — мгновенная и без ожидания сервера: нажимать можно сколько угодно
  быстро, на сервер уходит итог (см. «Данные на устройстве»); на нажатие даётся
  тактильный отклик.
- Нижняя навигация: вкладки «Привычки» и «Настройки» и кнопка «+» — экран создания
  привычки.
- Язык и тема хранятся на сервере и запоминаются на устройстве, поэтому приложение
  сразу открывается в них, не дожидаясь ответа сервера. Тексты интерфейса — в
  `strings.ts`; ошибки API показываются по коду ошибки на языке интерфейса.
- Тёмная тема — те же дизайн-токены с другими значениями (`styles/variables.css`,
  `:root[data-theme="dark"]`); фон и шапка Telegram перекрашиваются вместе с темой.
- У каждой привычки свой цвет: в нём её сетка, кнопка отметки и весь экран привычки.

## Данные на устройстве

Привычки и настройки живут на устройстве (`src/data/`), и в Mini App, и в
веб-приложении:

- **Изменения применяются сразу.** Отметка, новая или изменённая привычка, удаление,
  настройка — видны мгновенно и складываются в очередь операций (`localStorage`, ключ
  `streak:changes`). Очередь уходит на сервер одним запросом `POST /sync` через
  `SYNC_DELAY_MS` после первого неотправленного изменения, сразу — когда приложение
  сворачивают или закрывают (`keepalive`), и повторяется, пока нет связи (`online`,
  возврат в приложение, паузы `SYNC_RETRY_MS`). Лишнее склеивается до отправки: десять
  быстрых нажатий на одну привычку — одна операция, привычка, созданная и удалённая без
  связи, не уходит вовсе.
- **Ответ сервера — новый снимок.** `POST /sync` возвращает состояние после операций;
  оно хранится на устройстве (`streak:data`), отправленное уходит из очереди. Экран
  показывает снимок плюс ещё не отправленные операции, посчитанные на текущий день
  отметки (`derive.ts` — так же, как сервер: расписание, история, серии, «Отмечать за
  вчера», пояс), поэтому в полночь список переходит на новый день и без сети.
- **Открытие — сразу.** Приложение открывается на сохранённом снимке, без скелетона, и
  тут же спрашивает сервер о новостях (другое устройство, бот). Возврат в приложение
  тоже спрашивает — не чаще `SYNC_REFRESH_MIN_MS`.
- **Без сети.** Установленное веб-приложение открывается и без интернета: оболочку и
  скрипт Telegram SDK отдаёт service worker (`sw.ts`), сессия проверяется в фоне
  (`web/bootstrap.ts`). Mini App без интернета не открыть — его загружает сам Telegram,
  — но связь, пропавшая при открытом приложении, ему не мешает, а сделанное без неё
  сохранится и уйдёт позже.
- **Проверки — тоже на устройстве.** Форма привычки сразу говорит о дубликате названия
  и пределе привычек (`MAX_HABITS_PER_USER`), как сказал бы сервер. Если сервер всё же
  отверг изменение (например, другое устройство заняло название), оно пропадает с
  экрана и показывается диалог с причиной; отвергнутая настройка — тоже.
- **Новая привычка без связи** получает id устройства (`ref`, колонка
  `tasks.client_ref`): повтор того же запроса не создаёт вторую привычку, а её отметки,
  сделанные до ответа, сервер находит по этому id. На экране она до конца запуска
  остаётся под временным отрицательным id.
- Данные принадлежат одному аккаунту (пользователь Telegram или веб-сессия — по
  отпечатку токена, сам токен лежит только в `streak:session`): другой аккаунт на том же
  устройстве начинает с нуля, а выход из аккаунта стирает его данные с устройства.
  Отзыв, поиск города и админ-панель работают только со связью; админ-панель — только в
  Telegram.
- **Вход по ссылке установки** (`web/handoff.ts`): если у гостя на устройстве уже есть
  привычки, а ссылка ведёт в другой аккаунт, приложение (и страница установки на
  Android) сначала спрашивает — ссылку мог прислать кто-то другой.
- Каталог поясов и лимит названия подгружаются через `PREFETCH_DELAY_MS` после
  открытия; каталог хранится на устройстве (обновляется раз в 12 часов) — выбор пояса
  открывается сразу и без сети. Аккаунт веб-приложения тоже запоминается
  (`web/account.ts`); ряд «Аккаунт» без связи не пропадает — если аккаунт ещё ни разу не
  загружался, в нём «Нет связи», а нажатие пробует снова. Ни одна настройка из
  интерфейса без связи не исчезает.
- Страница установки — отдельный файл (lazy): приложение его не загружает. Картинка
  иконки на экранах — `icons/app-icon.webp`; PNG-иконки нужны только системе и не
  входят в кеш service worker.

## Android

iPhone — эталон: его вид и поведение неизменны. Android подтягивается к нему двумя
способами.

**Как на iPhone.** `requestFullscreen()` и `disableVerticalSwipes()` вызываются на обеих
платформах (см. «Поведение»). До этого Android открывался «шторкой»: приложение
занимало не весь экран, закрывалось свайпом вниз, а прокрутка списка то и дело утягивала
за собой само окно — из-за чего закреплённые шапка и нижняя навигация дрожали.

**Своё оформление там, где вебвью не тянет общее.** `main.tsx` ставит на `<html>`
атрибут `data-platform` (`android` / `ios` / `other`) по `WebApp.platform`, и по нему
включаются правки в `styles/variables.css` (в конце файла) и в модулях `TabBar`/
`CollapsingHeader`:

- матовое стекло навигации и подложки шапки заменено сплошной заливкой. Её цвета — те же
  полупрозрачные значения, заранее наложенные на цвет фона, поэтому вид почти не
  меняется; вебвью Android иначе пересчитывает `backdrop-filter` на каждом кадре
  прокрутки, и закреплённые поверхности отстают от содержимого;
- закреплённые элементы получают `will-change: transform` — собственный слой
  компоновщика, иначе их положение считается на основном потоке;
- размытие свёрнутого заголовка при появлении выключено (движение и проявление
  остались).

Правил «для Android» больше нигде нет: всё остальное — общий код.

Отступы безопасных зон в полноэкранном режиме приходят асинхронно, поэтому
пересчитываются по событиям `safeAreaChanged`, `contentSafeAreaChanged`,
`fullscreenChanged` и `fullscreenFailed` — и только по ним. На `viewportChanged`
подписываться нельзя: Android шлёт его и при смене высоты окна, в том числе когда
появляется нижняя кнопка Telegram (форма привычки), а отступы в этот
момент отвечают уже другой раскладке клиента — экран уезжает вниз, сверху открывается
зазор, нижняя навигация прилипает к краю.

«Резиновая» прокрутка (докрутил до края, тянешь — содержимое идёт за пальцем и
возвращается) — родная для iOS, её трогать нельзя. `overscroll-behavior: none` стоит
только на `body`; на `html` его быть не должно: к вьюпорту применяется значение
корневого элемента, и там это правило прокрутку у края обрубает.

## Экран «Привычки»

Крупный жирный заголовок «Привычки» слева сверху, под ним — до трёх секций, каждая
оформлена как одна общая белая карточка (в стиле сгруппированных списков iOS):

1. **На сегодня** — привычки, запланированные на сегодня; их можно отмечать
   (кнопка отметки активна).
2. Под приглушённым подзаголовком — **остальные** привычки (на сегодня не
   запланированы): тот же вид, но кнопка отметки неактивна — только просмотр
   прогресса.
3. Под подзаголовком «Заморожены» — **замороженные** привычки (тоже только просмотр).

Внутри карточки каждая привычка — это блок: строка с названием и круглой кнопкой
отметки за сегодня (незаполненный кружок ↔ заполненный с галочкой) и сетка 8×23
(последние 184 дня, `GRID_*` в `constants.ts`). У привычки «несколько раз в день»
(цель больше 1) кружок бледный с плюсом посередине: каждое нажатие плавно закрашивает
следующую долю обводки (дуга от 12 часов по часовой стрелке), последнее сразу ставит
обычный кружок с галочкой, следующее обнуляет день. Кнопка отметки при нажатии не сжимается, галочка
просто проявляется; зона нажатия на 6px шире кружка (невидимая). Частично выполненный день — не
выполнен (серии, «всего выполнено»), но в сетке его кружок закрашен по доле сделанного —
между пропуском и выполненным: 1 из 4 — на четверть (`history_counts`, `YearGrid`).
Соседние блоки разделяются тонкой линией. Закрашенный кружок сетки означает
выполненный день (статус `done`), бледно-голубой, перечёркнутый голубой снежинкой (шесть
жирных лучей от края до края; у всех привычек одного цвета) — невыполненный день заморозки, полупрозрачный — пропуск/нет данных. Самый
старый день — левый верхний угол, сегодня — правый нижний.

Нажатие на блок привычки (везде, кроме кнопки отметки) открывает экран привычки.

## Экран привычки

- **Последние 364 дня** — та же карточка привычки с кнопкой отметки, но с сеткой
  14×26.
- **Основное** — сетка 2×2: текущая серия, лучшая серия, всего выполнено и цель
  серии («Ежедневно», «Будние дни», «Выходные», «Через день», «Каждый месяц» или дни
  недели, например «Пн, Ср и Пт»).
- **Настройки** — «Редактировать привычку» (экран редактирования, см. ниже),
  «Автоотметка» — переключатель (только у привычек «раз в день»): бот сам отмечает
  привычку без напоминания с началом дня, с напоминаниями — сразу после последнего
  (`auto_mark`, операция `update`; при включении уже наступивший день отмечается сразу,
  даже если отметку с него сняли). Приложение показывает такую отметку само, как только
  ей пора (`data/derive.ts`, `applyAutoMark`): при открытии она уже стоит, не дожидаясь
  ответа сервера, и без сети; снятую пользователем не возвращает (`auto_mark_ahead`), —
  и «Заморозить привычку» (системный диалог
  объясняет, что будет с серией, отметками и напоминаниями; после согласия — возврат к
  списку) / «Разморозить привычку» (сразу, без диалога, экран остаётся открытым) —
  операция `freeze` в `POST /sync`.
  Под карточкой — отдельная кнопка-капсула «Удалить привычку» (52pt, красный текст по
  центру, как «Удалить будильник» в «Часах» iOS): подтверждение спрашивает системный
  диалог Telegram (`WebApp.showPopup` — на iPhone это обычный алерт iOS, его рисует сам
  Telegram); после удаления — возврат к списку. Если удалить не удалось, причина
  появляется под кнопкой.

Пока экран открыт, кнопка «Закрыть» Telegram заменена на «Назад» (`BackButton`),
а нижняя навигация уезжает вниз; при возврате список открывается на той же позиции
прокрутки. Отдельного запроса экран не делает: вся статистика приходит в
`GET /tasks`, поэтому отметка на экране привычки сразу видна и в списке.

## Создание и редактирование привычки

Один экран на оба случая (`HabitFormScreen`): открывается кнопкой «+» с крупным
заголовком «Новая привычка» или рядом «Редактировать привычку» — с заголовком
«Редактирование» и заполненными полями. Секции оформлены как на экране привычки, но
заголовки пишутся с заглавной буквы (не капсом) и начинаются там, где кончается
скругление карточки:

- **Информация** — название;
- **Частота** — «Повтор» (системное меню): по дням недели, «Через день» или «Каждый
  месяц». По дням недели — под рядом выбор дней (по умолчанию все), а в ряду — выбранные:
  «Каждый день», «Будние дни», «Выходные», «Пн, Ср и Пт», ни одного — «Никогда» (сохранить
  нельзя). «Через день» и «Каждый месяц» добавляют дату первого дня;
- **Цель** — сколько раз в день выполнить привычку: «1 раз в день», «3 раза в день», «5 раз в день» и степпер −/+
  (`Stepper`, удержание повторяет шаг; кнопки не подсвечиваются), от 1 до `MAX_TIMES_PER_DAY` (96);
- **Напоминание** — переключатель; включённый добавляет выбор времени и синюю строку
  «＋ Добавить напоминание» (ещё одно время, до 10; у добавленных слева красный «−» —
  убрать). В каждое время бот пришлёт в чат «🔔 Пора выполнить «…»» (в запланированные
  дни, если привычка ещё не отмечена);
- **Тема** — цвет привычки: ряд из 12 цветов, прокручивается по горизонтали. Форма
  сразу окрашивается в выбранный цвет.

Пока экран открыт, «Закрыть» Telegram заменена на «Назад» — выйти без сохранения, а
нижняя навигация скрыта. Сохраняет нижняя кнопка Telegram (`MainButton`) —
«Создать привычку» или «Сохранить» в цвете привычки; пока нет названия (или не
выбран ни один день), она серая и неактивна. После создания открывается список,
после редактирования — экран привычки. Ошибка (например, дубликат названия)
показывается под формой.

## Часовой пояс при первом запуске

Пока пояс не выбран (новый пользователь), приложение молча ставит пояс устройства
(`Intl.DateTimeFormat().resolvedOptions().timeZone`, напр. `Europe/Moscow`): его видно в
настройках — городом, давшим зоне имя, — и там же его можно поменять. Если сервер зону
не принял, остаётся UTC, а ошибка не показывается: пользователь ничего не менял.

## Подсветка нажатий

Нажимаемые ряды, привычки и кнопки подсвечиваются не через `:active` (он срабатывает от
любого касания, и при прокрутке загорается всё, через что прошёл палец), а атрибутом
`data-pressed`, который ставит `pressFeedback.ts`: касание подсвечивается через ~90 мс,
если палец не сдвинулся, а начало прокрутки подсветку снимает.

## Экран «Настройки»

Как «Настройки» iOS: белые карточки без подписей над ними, у каждого ряда —
иконка в цветной плашке.

0. **Аккаунт** — в обеих версиях: имя в Telegram и экран аккаунта (`AccountScreen`):
   дата регистрации, привычек, всего отметок, лучшая серия, устройств с входом в
   веб-приложение и под ним в той же карточке «Выйти на всех устройствах» — в обеих, пока
   есть откуда выходить (в веб-приложении — с других устройств, это остаётся в аккаунте;
   в Mini App — со всех). «Выйти из аккаунта» — только в веб-приложении, отдельной
   капсулой внизу, как «Удалить привычку». Гостю веб-приложения ряд предлагает привязать
   Telegram.
1. **Часовой пояс** — открывает выбор пояса: поиск и список «Город, Страна» со
   смещением (у выбранного — галочка). Ищет по городу, стране, имени зоны
   («Europe/Moscow» — так город находится и по-английски) и смещению («+3»).
   **Язык** — русский или английский; **Тема** — светлая, тёмная или системная
   (системными меню). **Напоминать отмечать** — экран напоминания «Пора отметить
   привычки»: время и дни недели (`CheckinReminderScreen`). **Уведомления** — в Mini
   App: напоминания и рассылки бота в Telegram (настройка аккаунта, выключение — с
   подтверждением); в веб-приложении: push на этом устройстве. **Добавить на рабочий
   стол** — установка веб-приложения (только в Telegram).
2. **Отмечать за вчера** — переключатель; под карточкой — пояснение.
3. **Написать отзыв** — открывает отдельный экран: карточка с полем, внизу справа в
   ней — круглая кнопка с самолётиком (как в Telegram; нижней кнопки Telegram нет).
   После отправки поле очищается, а отзыв встаёт первым в историю **«Ваши отзывы»** под
   полем — свои отзывы с датой и ответом администратора (`GET /reviews`; загружается
   заранее, через `PREFETCH_DELAY_MS` после открытия, — экран открывается сразу со списком). Отзыв уходит на
   сервер и появляется в админ-панели. **Политика конфиденциальности** и **Условия использования**
   — открывают документы (`legal.ts`).
4. **Админ-панель** — только у администраторов: переключает приложение в режим
   админ-панели.

Изменение применяется сразу и уходит на сервер (`PUT /settings`); если сервер его не
принял, оно откатывается, а под карточками появляется ошибка. После смены пояса или
режима «Отмечать за вчера» список привычек перезапрашивается — меняется день отметки.

Адаптивная тема следует за темой Telegram (`colorScheme`, событие `themeChanged`): на
iPhone Telegram по умолчанию переключается вместе с системой — и приложение вместе с
ним, без перезапуска. Вне Telegram — за системной темой браузера.

## Админ-панель

Режим приложения для администраторов (`admin/AdminApp.tsx`) в том же оформлении и на языке
интерфейса (русский или английский — `admin/adminStrings.ts`). Код панели собирается отдельным
файлом (`React.lazy`): остальные пользователи его не загружают, а администратору он
подгружается заранее, как только из настроек известно, что он администратор. Нижняя навигация заменена
своей — пять вкладок; вкладки делят таблетку по длине подписей, поэтому «Пользователи»
помещается целиком и на узком экране:

1. **Аналитика** — период (7, 30 или 90 дней) и секции: новые пользователи за период
   воронкой (запустили бота → из них открыли приложение → из них добавили привычку) и
   сейчас в приложении, график числа пользователей, активность (DAU, WAU, MAU, их
   отношение, график DAU), аудитория (пользуются, не открывали приложение, заблокировали
   бота), привычки тех, кто пользуется приложением (в среднем, всего, распределение;
   заблокировавшие бота не считаются) и доля выполнения по дням. На графике день
   выбирается пальцем — его значение видно в шапке карточки; кнопка в углу карточки
   показывает те же данные таблицей.
2. **Пользователи** — как выбор часового пояса: поиск и список (имя и id), страницы
   догружаются при прокрутке. Под поиском — кнопка «Фильтры» (экран с рядом на каждый
   признак и нижней кнопкой «Показать · N») и выбранные условия капсулами; нажатие на
   капсулу снимает условие. Профиль (поверх вкладки, без нижней навигации) — данные,
   статус, отзывы и действия: сообщение от бота (открывает экран написания), блокировка
   и удаление (с подтверждением системным диалогом Telegram). Ряд «Привычки» в профиле
   открывает привычки этого пользователя — тот же экран, что он видит у себя
   (`HabitsList`), с его днём отметки и подзаголовком, только для просмотра: отмечать
   и открывать привычки здесь нельзя.
3. **Отзывы** — список всех отзывов; отзыв целиком — ответить (экран написания; бот
   пришлёт ответ в Telegram) и перейти к профилю автора.
4. **Рассылка** — кому (те же фильтры, что у пользователей, и число получателей), текст,
   фото или видео, кнопка под сообщением («Открыть приложение», «Написать отзыв» или
   «Добавить привычку») и
   отправка с подтверждением; над формой — ход последней рассылки. Пока в поле текста
   (или в поиске пользователей) открыта клавиатура, нижняя навигация спрятана.
5. **Настройки** — язык и тема (те же, что в настройках приложения: смена видна сразу
   везде), администраторы (добавить по id Telegram — экран с полем, забрать права — с
   подтверждением) и «Вернуться в приложение».

Всё, что в админ-панели пишут руками (сообщение, ответ, id администратора), пишется на
отдельном экране (`ComposeScreen`), а не в диалоге поверх содержимого: поле во всю
ширину растёт вместе с текстом, нижняя навигация убрана, а отправляет нижняя кнопка
Telegram — она сама встаёт над клавиатурой. Подтверждения («Удалить», «Заблокировать»,
«Отправить рассылку») спрашивает системный диалог Telegram.

## Запуск

```bash
cd frontend
npm install

cp .env.example .env          # Windows: copy .env.example .env
# Указать VITE_API_BASE_URL — адрес API-сервера

npm run dev                   # разработка (http://127.0.0.1:5173)
npm run build                 # проверка типов + продакшен-сборка в dist/ (без source map)
npm run preview               # предпросмотр собранного (локально — порт 4173 за туннелем)
npm run typecheck             # только проверка типов (приложение и service worker)
npm test                      # vitest
```

## Переменные окружения (на этапе сборки Vite)

| Переменная | Назначение | Пример |
|---|---|---|
| `VITE_API_BASE_URL` | Базовый URL API-сервера (`/api` — через прокси nginx или Vite) | `/api` |
| `VITE_TELEGRAM_BOT_URL` | Ссылка «Открыть в Telegram» на странице установки | `https://t.me/onStreakBot` |

Локально — `frontend/.env`, на сервере — `frontend/.env.production` (оба не в git).
