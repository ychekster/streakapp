# StreakBot — Telegram Mini App

Приложение, в котором идёт вся работа с привычками: экран **«Привычки»** с сеткой
выполнения за полгода и отметкой в один тап, экран привычки, создание и
редактирование привычек (с напоминанием и цветом) и экран **«Настройки»** (часовой
пояс, язык, тема, «Отмечать за вчера», политика конфиденциальности и условия
использования, отзыв). Стиль — iOS 26 (Liquid Glass), светлая и тёмная темы; языки —
русский и английский. Для администраторов приложение переключается в режим
**админ-панели** — аналитика, пользователи, отзывы, рассылки, администраторы (на языке
интерфейса). Бот ([../README.md](../README.md)) открывает приложение, присылает
напоминания и рассылки.

Состоит из двух частей:

- **`backend/`** — API-сервер (FastAPI), владелец базы данных: модели, репозиторий,
  создание таблиц;
- **`frontend/`** — клиент (React + TypeScript + Vite), открывается как Telegram
  Web App.

## Backend (API)

### Технологии

FastAPI + uvicorn (async), SQLAlchemy 2.0 (async) + aiosqlite, alembic. Доступ к
данным — только через `Repository`.

### Как работает

- **Владелец данных.** API создаёт недостающие таблицы при старте (`create_all`),
  поэтому локально на SQLite миграции не обязательны. Схема версионируется alembic
  (см. «Миграции»).
- **Авторизация.** Каждый запрос обязан нести заголовок
  `Authorization: tma <initData>`. Подпись `initData` проверяется по алгоритму
  Telegram Web Apps (HMAC-SHA256 с секретом, выведенным из `BOT_TOKEN`) при
  **каждом** запросе; без валидной подписи — `401`. Дополнительно проверяется
  возраст подписи (`TMA_AUTH_TTL_SECONDS`, по умолчанию сутки; `0` — отключить).
- **Регистрация — автоматически.** При первом запросе пользователь создаётся в БД
  по данным из `initData`; @username и имя синхронизируются при следующих запросах.
  Отдельного онбординга нет.
- **Единый формат ошибок:** `{"error": {"code": "...", "message": "..."}}` с
  осмысленным HTTP-статусом — в том числе для неизвестного пути (`404 not_found`),
  чужого метода (`405`) и слишком большого тела (`413 payload_too_large`).
- **Транзакция — до ответа.** Сессия БД фиксируется (`commit`) до отправки ответа:
  если запись не удалась, клиент получает ошибку, а не `200` с несохранёнными данными.
- **Лимиты.** Тело запроса — не больше 64 КБ (проверяется до разбора и до
  авторизации). Один пользователь — не больше `TMA_RATE_LIMIT_BURST` запросов подряд
  и `TMA_RATE_LIMIT_PER_SECOND` в секунду, дальше `429 rate_limited` с `Retry-After`.
  Активных привычек у пользователя — не больше 50 (`409 habit_limit`).
- **Ответы не кешируются** (`Cache-Control: no-store`, `X-Content-Type-Options:
  nosniff`): это данные конкретного пользователя.
- **Документация API** (`/docs`, `/redoc`, `/openapi.json`) по умолчанию выключена —
  включается `TMA_DOCS_ENABLED=true` для разработки.
- **Активность.** Запрос пользователя отмечает его последний визит (не чаще раза в
  минуту) и день активности — из них аналитика админ-панели. Первый запрос — первое
  открытие приложения.
- **Блокировка.** Заблокированному администратором пользователю API отвечает
  `403 user_blocked`; напоминания и рассылки ему не приходят.
- **Админ-панель.** Каждый `/admin/*` проверяет, что пользователь из подписи — в таблице
  администраторов (иначе `403 admin_required`). Первый администратор — 6422071424
  (`SEED_ADMIN_IDS`), дальше список ведут в самой панели. Путь создания рассылки
  принимает тело до 50 МБ (видео), остальные — до 64 КБ.
- **Логи** — в stderr (и в файл `TMA_LOG_FILE`, если задан); трейсбэки — без значений
  переменных, чтобы в лог не попадали токен бота и initData. Запросы дольше секунды
  пишутся предупреждением.

### Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/tasks` | Список активных привычек с историей выполнения за последние 364 дня (14×26) и статистикой серий. |
| `POST` | `/tasks` | Создать привычку: название, частота (`daily` / `specific_days` + дни недели), время напоминания (`"09:00"` или `null`) и цвет. Дубликат названия — `409 duplicate_name`, больше 50 привычек — `409 habit_limit`. Управляющие символы в названии заменяются пробелом. |
| `PUT` | `/tasks/{task_id}` | Изменить привычку — те же поля, что при создании. История отметок сохраняется, серии пересчитываются по новому расписанию. Ответ — обновлённая привычка; нет такой активной привычки — `404`, дубликат названия — `409`. |
| `DELETE` | `/tasks/{task_id}` | Удалить привычку (мягко: `is_active = false`, история остаётся в базе, название снова свободно). Ответ `204`; нет такой активной привычки — `404`. |
| `POST` | `/tasks/{task_id}/toggle` | Отметить / снять отметку выполнения за сегодня. Возвращает обновлённую привычку. |
| `GET` | `/settings` | Текущие настройки: часовой пояс (с подписью на языке пользователя), язык (`ru` / `en`), тема (`light` / `dark` / `system`), «Отмечать за вчера». |
| `PUT` | `/settings` | Изменить настройки — передаются только меняемые поля: `{"timezone_city": 498817}` (пояс городом из справочника — `city_id` из `/meta/timezones`), `{"timezone": "Europe/Moscow"}` (или `"UTC+3"`; пояс без города), `{"language": "en"}`, `{"theme": "system"}`, `{"mark_yesterday": true}`. |
| `GET` | `/meta` | Справочные данные формы привычки: лимит длины названия. |
| `GET` | `/meta/timezones?language=ru` | Каталог часовых поясов для выбора в настройках — по поясу на зону, с запада на восток: зона IANA, город (`city_id` в справочнике, если он там есть), страна (на языке `language`) и текущее смещение. |
| `GET` | `/meta/timezones?language=ru&q=питер` | Поиск города (до 50): по названию на любом языке латиницей или кириллицей, с уточнением страны или региона (`портленд орегон`); по названию страны — ещё и её пояса; по смещению (`+3`) — пояса с ним. У одноимённых городов страны есть `region`. |
| `POST` | `/reviews` | Отзыв из настроек (`{"text": "…"}`, до 2000 символов, не больше 5 за сутки — иначе `429 review_limit`). Появляется в админ-панели. |
| `GET` | `/health` | Проверка живости сервиса и доступности БД: `200 {"status": "ok"}` или `503 database_unavailable`. Без авторизации. |

`GET /settings` возвращает и `is_admin` — по нему в настройках виден вход в
админ-панель.

Эндпоинты админ-панели (только администраторам; моменты времени — в UTC, «…Z»):

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/admin/analytics?days=30` | Аналитика за 7, 30 или 90 дней (UTC, сегодня включительно): пользователи (всего, новые за 7 и 30 дней, открывшие и не открывшие приложение, заблокировавшие бота, сейчас в приложении), аудитория без пересечений, DAU/WAU/MAU, привычки на пользователя и их распределение, доля выполнения; по дням — новые, всего, активные, запланировано и выполнено. |
| `GET` | `/admin/users?q=&cursor=&limit=` | Пользователи, новые сначала, страницами; `q` — имя, @username или id. |
| `GET` | `/admin/users/{id}` | Профиль: данные, статус, число привычек, отзывы. |
| `PUT` | `/admin/users/{id}/block` | `{"blocked": true}` — заблокировать, `false` — снять. Администратора — `409 user_is_admin`. |
| `DELETE` | `/admin/users/{id}` | Удалить пользователя со всеми данными. |
| `POST` | `/admin/users/{id}/message` | Личное сообщение от бота `{"text"}`. Ответ `{"delivered", "reason"}`: `bot_blocked` — пользователь заблокировал бота. |
| `GET` | `/admin/reviews?cursor=&limit=` | Отзывы всех пользователей, новые сначала, страницами. |
| `GET` | `/admin/reviews/{id}` | Отзыв. |
| `POST` | `/admin/reviews/{id}/reply` | Ответ на отзыв сообщением бота (с цитатой отзыва); дошедший ответ запоминается. |
| `GET` | `/admin/admins` | Администраторы. |
| `POST` | `/admin/admins` | Добавить `{"telegram_id"}`. |
| `DELETE` | `/admin/admins/{id}` | Убрать (себя — `409 cannot_remove_self`). |
| `GET` | `/admin/broadcasts/segments` | Сегменты рассылки с числом получателей: `all`, `active_7d`, `active_30d`, `never_opened`. |
| `POST` | `/admin/broadcasts` | Рассылка — multipart: `segment`, `text`, необязательно `media` (фото JPEG/PNG/WebP до 10 МБ или видео MP4 до 50 МБ; текст — подпись до 1024 символов). Копия сразу приходит автору, остальным рассылает бот. |
| `GET` | `/admin/broadcasts/{id}` | Ход рассылки: получателей, доставлено, не доставлено, статус. |

Формат привычки в ответе:

```jsonc
{
  "id": 12,
  "name": "Зарядка",
  "done_today": true,
  // запланирована ли на сегодня (по частоте/дням недели); false — только просмотр
  "scheduled_today": true,
  // частота: "daily" или "specific_days" + коды дней недели (для daily — [])
  "frequency_type": "specific_days",
  "days": ["mon", "wed", "fri"],
  // 364 булевых значения, старое → сегодня; true — день выполнен (статус done)
  "history": [false, true, false, /* ... */ true],
  "current_streak": 5,  // текущая серия, дней
  "best_streak": 21,    // лучшая серия за всё время
  "total_done": 96,     // сколько раз выполнена за всё время
  // время напоминания «ЧЧ:ММ» в поясе пользователя; null — без напоминания
  "reminder_time": "09:00",
  // цвет (тема) — ключ палитры: blue, lightblue, teal, green, yellow, orange, red,
  // pink, purple, indigo, brown, graphite
  "color": "green"
}
```

«Сегодня» вычисляется в часовом поясе пользователя (пока пояс не выбран — UTC);
индекс 0 в `history` — самый старый день, последний элемент — сегодня. В режиме
**«Отмечать за вчера»** всё считается от вчерашнего дня: отметка ставится за вчера,
`done_today` и `scheduled_today` — про вчера, история и серии заканчиваются вчера.
Напоминания этот режим не меняет — они про сегодняшний день.

Язык новому пользователю выбирается по языку его Telegram (русский — если Telegram
на русском, иначе английский); на нём же бот присылает напоминания.

Серия — подряд идущие выполненные дни. Её прерывает только пропущенный
запланированный день: у привычек «по дням недели» незапланированные дни серию не
рвут. Неотмеченный сегодняшний день текущую серию тоже не прерывает — день ещё не
закончился.

### Запуск

> Запускать **из корня репозитория** — относительный путь SQLite в `DATABASE_URL`
> отсчитывается от рабочей директории.

```bash
# из корня репозитория
pip install -r tma/backend/requirements.txt

python -m tma.backend.main
# или с автоперезагрузкой при разработке:
uvicorn tma.backend.main:app --reload --port 8000
```

### Миграции

```bash
# из корня репозитория
alembic upgrade head
```

Миграция `0003` удаляет колонки уведомлений и онбординга бота
(`users.morning_time`, `users.evening_time`, `users.is_registered`,
`users.is_active`, `tasks.reminder_time`). Для базы, созданной до этой версии, её
нужно применить перед запуском API: иначе создание новых пользователей упрётся в
NOT NULL-колонку `is_registered`.

Миграция `0004` добавляет `tasks.reminder_time` (напоминания из приложения; старые
значения из бота удалены миграцией `0003` и не оживают) и `tasks.color` (у
существующих привычек — `blue`). Без неё API не прочитает привычки.

Миграция `0005` добавляет настройки пользователя: `users.language` (у существующих —
`ru`), `users.theme` (`light`) и `users.mark_yesterday` (выключено). Без неё API не
прочитает пользователей.

Миграция `0006` добавляет `users.timezone_city` (город выбранного пояса).

Миграция `0007` добавляет индекс `ix_tasks_reminder_time`: бот каждую минуту выбирает
привычки по времени напоминания. Без неё всё работает, но медленнее на большой базе.

Миграция `0008` — данные админ-панели: у пользователей — первое открытие приложения,
последний визит, блокировка бота и блокировка администратором; таблицы `admins` (с
первым администратором 6422071424), `reviews`, `user_activity` и `broadcasts`. История
активности восстанавливается по дням регистрации и отметкам привычек. Без неё API не
прочитает пользователей.

> Перед миграцией сделайте копию базы: `python scripts/backup_db.py` (база в режиме
> WAL — простое копирование файла на работающих процессах может потерять последние
> изменения).

### Переменные окружения (из общего `.env`)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен бота — для проверки подписи `initData` | — (обязательна) |
| `DATABASE_URL` | Строка подключения к БД (async-драйвер) | `sqlite+aiosqlite:///./streakbot.db` |
| `DB_POOL_SIZE`, `DB_MAX_OVERFLOW` | Пул соединений с PostgreSQL (у SQLite не используется) | `10`, `20` |
| `TMA_HOST` | Хост API-сервера (`0.0.0.0` — все интерфейсы, например в Docker) | `127.0.0.1` |
| `TMA_PORT` | Порт API-сервера | `8000` |
| `TMA_ALLOWED_ORIGINS` | Разрешённые источники CORS (через запятую; `*` — любой) | `*` |
| `TMA_AUTH_TTL_SECONDS` | Максимальный возраст `initData` в секундах (`0` — без проверки) | `86400` |
| `TMA_RATE_LIMIT_BURST` | Запросов одного пользователя подряд (`0` — без лимита) | `60` |
| `TMA_RATE_LIMIT_PER_SECOND` | Скорость пополнения лимита, запросов в секунду | `5` |
| `TMA_DOCS_ENABLED` | Документация API `/docs`, `/redoc`, `/openapi.json` | `false` |
| `TMA_LOG_LEVEL` | Уровень логов API | `INFO` |
| `TMA_LOG_FILE` | Файл логов API с ротацией (пусто — только stderr) | — |

## Frontend (TMA)

### Технологии

React + TypeScript + Vite, стилизация — **CSS Modules** + CSS-переменные
(дизайн-токены). Никаких UI-китов и компонентных библиотек — только нативный
браузерный рендеринг.

### Поведение

- При открытии вызывает `WebApp.ready()` и `WebApp.expand()` — приложение во весь
  экран, без верхнего зазора; фон/шапка красятся под дизайн-токен фона.
- Авторизация — автоматически через `initData` из `window.Telegram.WebApp`,
  которая уходит в заголовке каждого запроса.
- На время загрузки показывается скелетон; ошибки сети/API, пустой список и запуск
  вне Telegram отображаются понятными сообщениями. Запрос, на который сервер не
  ответил за 15 секунд, считается ошибкой сети — экран не зависает в загрузке.
- Ошибка отрисовки не оставляет пустой экран: `ErrorBoundary` показывает сообщение и
  кнопку перезапуска.
- Отметка выполнения — оптимистичная: состояние меняется мгновенно, при ошибке
  запроса откатывается (только эта привычка — отметки других остаются); на нажатие
  даётся тактильный отклик.
- Нижняя навигация: вкладки «Привычки» и «Настройки» и кнопка «+» — экран создания
  привычки.
- Язык и тема хранятся на сервере и запоминаются на устройстве, поэтому приложение
  сразу открывается в них, не дожидаясь ответа сервера. Тексты интерфейса — в
  `strings.ts`; ошибки API показываются по коду ошибки на языке интерфейса.
- Тёмная тема — те же дизайн-токены с другими значениями (`styles/variables.css`,
  `:root[data-theme="dark"]`); фон и шапка Telegram перекрашиваются вместе с темой.
- У каждой привычки свой цвет: в нём её сетка, кнопка отметки и весь экран привычки.

### Экран «Привычки»

Крупный жирный заголовок «Привычки» слева сверху, под ним — две секции, каждая
оформлена как одна общая белая карточка (в стиле сгруппированных списков iOS):

1. **На сегодня** — привычки, запланированные на сегодня; их можно отмечать
   (кнопка отметки активна).
2. Под приглушённым подзаголовком — **остальные** привычки (на сегодня не
   запланированы): тот же вид, но кнопка отметки неактивна — только просмотр
   прогресса.

Внутри карточки каждая привычка — это блок: строка с названием и круглой кнопкой
отметки за сегодня (незаполненный кружок ↔ заполненный с галочкой) и сетка 7×26.
Соседние блоки разделяются тонкой линией. Закрашенный кружок сетки означает
выполненный день (статус `done`), полупрозрачный — пропуск/нет данных. Самый
старый день — левый верхний угол, сегодня — правый нижний.

Нажатие на блок привычки (везде, кроме кнопки отметки) открывает экран привычки.

### Экран привычки

- **Последние 364 дня** — та же карточка привычки с кнопкой отметки, но с сеткой
  14×26; нижние 7 рядов совпадают с сеткой в списке.
- **Основное** — сетка 2×2: текущая серия, лучшая серия, всего выполнено и цель
  серии («Ежедневно», «Будни», «Выходные» или дни недели, например «Пн, Ср, Пт»).
- **Настройки** — «Редактировать привычку» (экран редактирования, см. ниже) и
  «Удалить привычку»: диалог подтверждения по центру экрана («Отменить» /
  «Удалить»); после удаления — возврат к списку. Если удалить не удалось, диалог
  остаётся открытым и показывает ошибку.

Пока экран открыт, кнопка «Закрыть» Telegram заменена на «Назад» (`BackButton`),
а нижняя навигация уезжает вниз; при возврате список открывается на той же позиции
прокрутки. Отдельного запроса экран не делает: вся статистика приходит в
`GET /tasks`, поэтому отметка на экране привычки сразу видна и в списке.

### Создание и редактирование привычки

Один экран на оба случая (`HabitFormScreen`): открывается кнопкой «+» с крупным
заголовком «Новая привычка» или рядом «Редактировать привычку» — с заголовком
«Редактирование» и заполненными полями. Секции оформлены как на экране привычки, но
заголовки пишутся с заглавной буквы (не капсом) и начинаются там, где кончается
скругление карточки:

- **Информация** — название;
- **Частота** — «Повторять»: «Каждый день» или «По дням» (системное меню); «По
  дням» добавляет ряд дней недели;
- **Напоминание** — переключатель; включённый добавляет выбор времени. В это время
  бот пришлёт в чат «🔔 Пора выполнить «…»» (в запланированные дни, если привычка
  ещё не отмечена);
- **Тема** — цвет привычки: ряд из 12 цветов, прокручивается по горизонтали. Форма
  сразу окрашивается в выбранный цвет.

Пока экран открыт, «Закрыть» Telegram заменена на «Назад» — выйти без сохранения, а
нижняя навигация скрыта. Сохраняет нижняя кнопка Telegram (`MainButton`) —
«Создать привычку» или «Сохранить» в цвете привычки; пока нет названия (или не
выбран ни один день), она серая и неактивна. После создания открывается список,
после редактирования — экран привычки. Ошибка (например, дубликат названия)
показывается под формой.

### Экран «Настройки»

Как «Настройки» iOS: белые карточки без подписей над ними, у каждого ряда —
иконка в цветной плашке.

1. **Часовой пояс** — открывает выбор пояса: поиск и список «Город, Страна» со
   смещением (у выбранного — галочка). Ищет по городу, стране, имени зоны
   («Europe/Moscow» — так город находится и по-английски) и смещению («+3»).
   **Язык** — русский или английский; **Тема** — светлая, тёмная или адаптивная
   (системными меню).
2. **Отмечать за вчера** — переключатель; под карточкой — пояснение.
3. **Написать отзыв** — диалог с полем для отзыва: он уходит на сервер и появляется в
   админ-панели. **Политика конфиденциальности** и **Условия использования** — открывают
   документы (`legal.ts`).
4. **Админ-панель** — только у администраторов: переключает приложение в режим
   админ-панели.

Изменение применяется сразу и уходит на сервер (`PUT /settings`); если сервер его не
принял, оно откатывается, а под карточками появляется ошибка. После смены пояса или
режима «Отмечать за вчера» список привычек перезапрашивается — меняется день отметки.

Адаптивная тема следует за темой Telegram (`colorScheme`, событие `themeChanged`): на
iPhone Telegram по умолчанию переключается вместе с системой — и приложение вместе с
ним, без перезапуска. Вне Telegram — за системной темой браузера.

### Админ-панель

Режим приложения для администраторов (`AdminApp.tsx`) в том же оформлении и на языке
интерфейса (русский или английский — `adminStrings.ts`). Нижняя навигация заменена
своей — пять вкладок; вкладки делят таблетку по длине подписей, поэтому «Пользователи»
помещается целиком и на узком экране:

1. **Аналитика** — период (7, 30 или 90 дней) и секции: пользователи (всего, новые, сейчас
   в приложении, график числа пользователей), активность (DAU, WAU, MAU, их отношение,
   график DAU), аудитория (пользуются, не открывали приложение, заблокировали бота),
   привычки (в среднем, всего, распределение) и доля выполнения по дням. На графике день
   выбирается пальцем — его значение видно в шапке карточки; кнопка в углу карточки
   показывает те же данные таблицей.
2. **Пользователи** — как выбор часового пояса: поиск и список (имя и id), страницы
   догружаются при прокрутке. Профиль (поверх вкладки, без нижней навигации) — данные,
   статус, отзывы и действия: сообщение от бота, блокировка и удаление (с подтверждением).
3. **Отзывы** — список всех отзывов; отзыв целиком — ответить (бот пришлёт ответ в
   Telegram) и перейти к профилю автора.
4. **Рассылка** — кому (сегмент и число получателей), текст, фото или видео и отправка с
   подтверждением; над формой — ход последней рассылки.
5. **Настройки** — язык и тема (те же, что в настройках приложения: смена видна сразу
   везде), администраторы (добавить по id Telegram, забрать права) и «Вернуться в
   приложение».

## Подключение к боту

На `/start` бот присылает приветствие с inline-кнопкой **«📱 Открыть приложение»**
(`web_app`), а также ставит такую же кнопку в меню слева от поля ввода. Адрес
берётся из `TMA_URL` в `.env` — это публичный **HTTPS**-адрес собранного фронтенда
(требование Telegram для Web App). Локально его удобно получить туннелем
(например, через `cloudflared`/`ngrok`) к раздаче собранного `dist/`
(`vite preview`). Dev-сервер (`npm run dev`) через туннель публиковать не стоит: он
медленный (десятки несобранных модулей) и рассчитан только на локальную разработку.

### Общий порядок запуска

1. Заполнить корневой `.env` (`BOT_TOKEN`, `TMA_URL`, при необходимости
   `DATABASE_URL`, `TMA_HOST`, `TMA_PORT`).
2. Применить миграции: `alembic upgrade head` (из корня репозитория).
3. Запустить API: `python -m tma.backend.main` (из корня репозитория).
4. Собрать/поднять фронтенд и сделать его доступным по HTTPS (`TMA_URL`).
5. Запустить (или перезапустить) бота: `python -m bot.main`.

> **SQLite в продакшене.** Для локальной разработки SQLite достаточно. Для
> продакшена переходите на PostgreSQL (см. [docs/SCALING.md](../docs/SCALING.md)):
> меняется только `DATABASE_URL`.
