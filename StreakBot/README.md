# StreakBot

Трекер привычек в Telegram: пользователь создаёт привычки, отмечает выполнение и
следит за прогрессом на сетке — всё внутри **Telegram Mini App**. Бот приветствует
пользователя, открывает приложение и присылает напоминания о привычках.

Проект состоит из трёх частей:

| Часть | Где | Что делает |
|---|---|---|
| Бот | `bot/` | `/start` → приветствие с кнопкой запуска Mini App; кнопка приложения в меню чата; напоминания о привычках; рассылки из админ-панели |
| API | `tma/backend/` | FastAPI: авторизация по `initData`, привычки, настройки, отзывы, админ-панель; владеет базой данных |
| Фронтенд | `tma/frontend/` | React + TypeScript: экраны «Привычки», «Настройки» (пояс, язык, тема, «Отмечать за вчера», отзыв), экран привычки со статистикой, создание и редактирование привычки; русский и английский, светлая и тёмная темы; для администраторов — админ-панель (аналитика, пользователи и отзывы, рассылки, администраторы) |

Подробности о приложении — в [tma/README.md](tma/README.md), об архитектуре — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Бот

Единственная команда — `/start`. В ответ бот присылает приветствие (жирный
заголовок, абзац о проекте, жирный призыв) и inline-кнопку
**«📱 Открыть приложение»**. Та же кнопка стоит в меню слева от поля ввода. Других
команд нет: всё взаимодействие идёт в приложении.

### Напоминания

Если у привычки включено напоминание (настраивается в приложении), в заданное время
бот пишет в чат: **«🔔 Пора выполнить «Название привычки»»** (на английском, если
в приложении выбран английский). Время — в часовом поясе пользователя из настроек
приложения. Напоминание приходит только в дни, на которые привычка запланирована, и
только пока она за этот день не отмечена.

Раз в минуту бот спрашивает у базы данных, чьё время наступило (`bot/reminders.py`),
поэтому изменения из приложения подхватываются сразу. Бот только читает базу — через
слой данных API (`tma/backend`); ведёт её API. Рассылка идёт параллельно по
пользователям, но в пределах лимитов Bot API (не больше 25 сообщений в секунду всем и
одного в секунду одному чату), и честно: много напоминаний у одного пользователя не
задерживают остальных.

При старте бот удаляет список команд, который регистрировали прежние версии, — иначе
Telegram продолжал бы показывать пользователям несуществующие команды.

### Рассылки и учёт пользователей

Рассылку пишут в админ-панели приложения, а отправляет бот (`bot/broadcasts.py`): раз
в несколько секунд он берёт рассылку из очереди в базе и отправляет её получателям
пачками — в общем темпе с напоминаниями (`bot/pacing.py`), с учётом прогресса после
каждой пачки, так что перезапуск бота рассылку не прерывает. Фото и видео уже загружены
в Telegram (копия рассылки приходит её автору первой) и отправляются по `file_id`.

Для админ-панели бот отмечает в базе события Telegram: `/start` записывает пользователя
(так видны и те, кто ещё не открывал приложение), а блокировку и разблокировку бота он
узнаёт из обновления `my_chat_member` и из ответа 403 на отправку. Заблокировавшим бота
рассылки не отправляются.

### Технологический стек бота

| Компонент | Библиотека |
|---|---|
| Telegram API | `aiogram` 3.x |
| База данных (напоминания, рассылки, учёт пользователей) | `SQLAlchemy` 2.0 (async) + `aiosqlite`, `pytz`, `Babel` (нужен слою данных API) |
| Конфиг | `pydantic-settings` (`.env`) |
| Логи | `loguru` |

### Запуск

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env          # Windows: copy .env.example .env
# Заполнить .env: BOT_TOKEN от @BotFather и TMA_URL — HTTPS-адрес фронтенда

python -m bot.main
```

Запускать из корня репозитория — так же, как API: относительный путь SQLite в
`DATABASE_URL` отсчитывается от рабочей директории. Базу данных создаёт и
мигрирует API-сервер (см. [tma/README.md](tma/README.md)); бот через тот же слой
данных читает из неё напоминания и рассылки и отмечает события Telegram.

## Переменные окружения

Общий `.env` в корне репозитория читают и бот, и API.

| Переменная | Кто использует | Назначение | Обязательна |
|---|---|---|---|
| `BOT_TOKEN` | бот, API | Токен бота от @BotFather (API проверяет им подпись `initData`) | да |
| `TMA_URL` | бот | Публичный HTTPS-адрес фронтенда Mini App | да |
| `DATABASE_URL` | API, alembic, бот | Строка подключения к БД (async-драйвер) | нет (дефолт — SQLite) |
| `TMA_HOST`, `TMA_PORT` | API | Хост и порт API-сервера (`127.0.0.1:8000` — только локально) | нет |
| `LOG_LEVEL`, `LOG_FILE` | бот | Уровень и файл логов (`INFO`, `logs/bot.log`) | нет |

Остальные переменные API — в [tma/README.md](tma/README.md).

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest            # из корня репозитория
```

Тесты подменяют токен бота и базу на временные — настоящие `.env` и `streakbot.db` они
не трогают.

## Резервная копия базы

База SQLite работает в режиме WAL: свежие изменения какое-то время лежат в
`streakbot.db-wal`, поэтому просто копировать `streakbot.db` при запущенных API и боте
нельзя — можно потерять последние изменения. Копию снимает скрипт (через backup API
SQLite, согласованный снимок):

```bash
python scripts/backup_db.py             # → streakbot_backup_<дата-время>.db
```

После остановки всех процессов SQLite сам переносит WAL в основной файл, и
`streakbot.db` можно копировать как обычно.

## Масштабирование

Переход с SQLite на PostgreSQL описан в [docs/SCALING.md](docs/SCALING.md):
по сути — поменять `DATABASE_URL`, добавить `asyncpg` и применить миграции.
