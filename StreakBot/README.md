# StreakBot

Трекер привычек в Telegram: пользователь создаёт привычки, отмечает выполнение и
следит за прогрессом на сетке — всё внутри **Telegram Mini App**. Бот приветствует
пользователя, открывает приложение и присылает напоминания о привычках.

Проект состоит из трёх частей:

| Часть | Где | Что делает |
|---|---|---|
| Бот | `bot/` | `/start` → приветствие с кнопкой запуска Mini App; кнопка приложения в меню чата; напоминания о привычках |
| API | `tma/backend/` | FastAPI: авторизация по `initData`, привычки, настройки; владеет базой данных |
| Фронтенд | `tma/frontend/` | React + TypeScript: экраны «Привычки», «Настройки», экран привычки со статистикой, создание и редактирование привычки |

Подробности о приложении — в [tma/README.md](tma/README.md), об архитектуре — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Бот

Единственная команда — `/start`. В ответ бот присылает приветствие (жирный
заголовок, абзац о проекте, жирный призыв) и inline-кнопку
**«📱 Открыть приложение»**. Та же кнопка стоит в меню слева от поля ввода. Других
команд нет: всё взаимодействие идёт в приложении.

### Напоминания

Если у привычки включено напоминание (настраивается в приложении), в заданное время
бот пишет в чат: **«🔔 Пора выполнить «Название привычки»»**. Время — в часовом поясе
пользователя из настроек приложения. Напоминание приходит только в дни, на которые
привычка запланирована, и только пока она за этот день не отмечена.

Раз в минуту бот спрашивает у базы данных, чьё время наступило (`bot/reminders.py`),
поэтому изменения из приложения подхватываются сразу. Бот только читает базу — через
слой данных API (`tma/backend`); ведёт её API.

При старте бот удаляет список команд, который регистрировали прежние версии, — иначе
Telegram продолжал бы показывать пользователям несуществующие команды.

### Технологический стек бота

| Компонент | Библиотека |
|---|---|
| Telegram API | `aiogram` 3.x |
| База данных (чтение напоминаний) | `SQLAlchemy` 2.0 (async) + `aiosqlite`, `pytz` |
| Конфиг | `pydantic-settings` (`.env`) |
| Логи | `loguru` |

### Запуск

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env          # Windows: copy .env.example .env
# Заполнить .env: BOT_TOKEN от @BotFather и TMA_URL — HTTPS-адрес фронтенда

python -m bot.main
```

Запускать из корня репозитория — так же, как API: относительный путь SQLite в
`DATABASE_URL` отсчитывается от рабочей директории. Базу данных создаёт и
мигрирует API-сервер (см. [tma/README.md](tma/README.md)); бот из неё только читает.

## Переменные окружения

Общий `.env` в корне репозитория читают и бот, и API.

| Переменная | Кто использует | Назначение | Обязательна |
|---|---|---|---|
| `BOT_TOKEN` | бот, API | Токен бота от @BotFather (API проверяет им подпись `initData`) | да |
| `TMA_URL` | бот | Публичный HTTPS-адрес фронтенда Mini App | да |
| `DATABASE_URL` | API, alembic, бот | Строка подключения к БД (async-драйвер) | нет (дефолт — SQLite) |
| `TMA_HOST`, `TMA_PORT` | API | Хост и порт API-сервера | нет |
| `LOG_LEVEL`, `LOG_FILE` | бот | Уровень и файл логов (`INFO`, `logs/bot.log`) | нет |

Остальные переменные API — в [tma/README.md](tma/README.md).

## Масштабирование

Переход с SQLite на PostgreSQL описан в [docs/SCALING.md](docs/SCALING.md):
по сути — поменять `DATABASE_URL`, добавить `asyncpg` и применить миграции.
