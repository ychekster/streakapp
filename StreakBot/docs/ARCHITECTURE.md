# Архитектура StreakBot

Документ описывает ключевые архитектурные решения и причины, по которым они
приняты.

## Компоненты и поток данных

```
                 /start
Telegram ────────────────────► Бот (bot/) ──► приветствие + кнопка Mini App
   │                              │
   │                              └─ раз в минуту: напоминания ◄── чтение БД (tma/backend)
   │
   │ кнопка «Открыть приложение» (web_app)
   ▼
Mini App (tma/frontend)
   │  HTTP, Authorization: tma <initData>
   ▼
API (tma/backend, FastAPI)
   │
get_current_user (проверка подписи initData)
   │
get_db_user (запись пользователя; создаётся при первом запросе)
   │
Router → Service (сборка привычек, отметка, настройки)
   │
Repository (CRUD)
   │
SQLAlchemy (async session)
   │
SQLite / PostgreSQL
```

Бот и API — два независимых процесса. Общие у них `.env`, `BOT_TOKEN` (бот им
авторизуется в Telegram, API — проверяет подпись `initData`) и база данных: её ведёт
API, а бот только читает из неё напоминания через тот же слой данных.

## Слои и ответственность

| Слой | Где | Отвечает за |
|---|---|---|
| Бот | `bot/*` | `/start`, кнопка Mini App в меню чата, напоминания о привычках |
| Конфиг API | `tma/backend/config.py` | Загрузка и валидация `.env` (pydantic-settings) |
| Авторизация | `tma/backend/auth.py` | Проверка подписи `initData` (HMAC-SHA256) |
| Зависимости | `tma/backend/dependencies.py` | DI: сессия + репозиторий, пользователь Telegram, запись в БД |
| Роутеры | `tma/backend/routers/*` | HTTP-эндпоинты `/tasks`, `/settings`, `/meta` |
| Сервисы | `tma/backend/services.py` | История выполнения, создание/изменение привычки, отметка, настройки, наступившие напоминания |
| Валидация | `tma/backend/validation.py` | Проверка названия, частоты, времени напоминания, цвета, часового пояса, языка, темы |
| Часовые пояса | `tma/backend/timezones.py` | Каталог поясов, поиск города, разбор `UTC±N`, подписи на языке интерфейса |
| Справочник городов | `tma/backend/cities.py`, `tma/backend/data/cities.tsv.gz` | ~64 тыс. городов GeoNames с зонами и названиями; поиск по названию |
| Репозиторий | `tma/backend/repository.py` | Единственная точка доступа к БД |
| Модели | `tma/backend/models.py` | ORM-схема (User, Task, TaskLog) |
| Миграции | `alembic/` | Версионирование схемы |

## Ключевые решения

### Бот — точка входа и напоминания
Вся работа с привычками идёт в Mini App, поэтому у бота нет ни FSM, ни middlewares,
ни команд, кроме `/start`. На `/start` он присылает приветствие и inline-кнопку
`web_app`; та же кнопка стоит в меню чата (`MenuButtonWebApp`). Поэтому `TMA_URL`
для бота обязателен.

- **Напоминания — опрос базы раз в минуту.** Время напоминания привычки задаётся в
  приложении и хранится в `tasks.reminder_time` (в поясе пользователя). Цикл
  `bot/reminders.py` в начале каждой минуты спрашивает `services.due_reminders`, у
  каких привычек время напоминания в поясе владельца совпало с этой минутой, и
  присылает «🔔 Пора выполнить «…»». Напоминание приходит только в запланированные
  дни и только пока привычка за день не отмечена. Опрос, а не расписание в памяти
  (как у прежнего APScheduler): привычки меняет другой процесс — API, и так изменения
  подхватываются сразу, без синхронизации и восстановления заданий после рестарта.
- **Каждая минута — один раз.** Цикл помнит последнюю обработанную минуту и, если
  отстал (долгая отправка, пауза процесса), досылает пропущенные — не дальше 5 минут
  назад. При старте обрабатывается и текущая минута: рестарт бота ровно в минуту
  напоминания может прислать его дважды, но не теряет его.
- **Сбой доставки не мешает остальным.** Заблокировавший бота пользователь
  (`TelegramForbiddenError`) и прочие ошибки Telegram логируются; на `RetryAfter`
  бот ждёт и повторяет отправку один раз.

- **Разметка через entities.** Жирные заголовок и призыв собираются через
  `aiogram.utils.formatting` (`Text`, `Bold`). Библиотека сама считает смещения
  entities (в UTF-16, с учётом эмодзи), поэтому тексты в `constants.py` хранятся в
  чистом виде, без экранирования и `parse_mode`.
- **Старое меню команд удаляется.** Список команд, зарегистрированный прежними
  версиями бота через `set_my_commands`, хранится на стороне Telegram. При старте
  бот вызывает `delete_my_commands`, чтобы пользователи не видели несуществующие
  команды.

### API — владелец данных
Модели, репозиторий и создание таблиц живут в `tma/backend`. При старте API
создаёт недостающие таблицы (`create_all`, существующие не меняет); схема
версионируется alembic. Бот в базу не пишет — только читает напоминания.

### Цвет привычки
У каждой привычки свой цвет (`tasks.color`) — ключ палитры (`blue`, `green`, …),
а не hex: сами цвета — дизайн-токены фронтенда (`--palette-*`), и их можно менять,
не трогая данные. Бэкенд проверяет только, что ключ из списка
`constants.HABIT_COLORS`. Во фронтенде корень карточки или экрана привычки получает
переменную `--habit-rgb`, и всё внутри (сетка, кнопка отметки, иконки показателей)
берёт цвет из неё.

### Регистрация пользователя при первом запросе
Отдельного онбординга нет. Зависимость `get_db_user` вызывает
`Repository.get_or_create_user` по данным из проверенной `initData`: при первом
открытии приложения запись создаётся, при последующих синхронизируются @username и
имя (если они не изменились, UPDATE не выполняется). Вставка обёрнута в SAVEPOINT:
если несколько первых запросов пришли параллельно и один уже создал запись,
остальные ловят `IntegrityError` и перечитывают её. FastAPI кеширует зависимости в
пределах запроса, поэтому `get_db_user` и обработчик маршрута работают с одним
репозиторием и одной сессией.

### Прогресс вычисляется, а не хранится
Отметки хранятся в `TaskLog` (одна запись на задачу и дату). История привычки —
364 булевых значения (сетка 14×26, старое → сегодня; список показывает последние
182) — каждый раз собирается по логам: день закрашен, если в эту дату есть лог со
статусом `done`. Так же, за один проход по логам, считаются текущая и лучшая серии
и общее число выполнений; какие пропуски рвут серию, решает расписание привычки
(`schedule.py`). Единственный источник правды — журнал отметок, рассинхронизация
исключена.

Приложение ставит только `pending` и `done` (переключение отметки за сегодня).
Статусы `skipped` и `missed` проставлял прежний бот; они оставлены в enum, чтобы
читались исторические записи, и в истории считаются невыполненными днями.

### Часовые пояса
«Сегодня» считается в поясе пользователя (`User.timezone`, строка IANA). Пояс
выбирается в настройках приложения городом: пользователь ищет свой город, а пояс —
зона этого города. Город хранится рядом с поясом (`User.timezone_city`, id в
справочнике), потому что у зоны много городов: выбравший Санкт-Петербург видит в
настройках «Санкт-Петербург», а не «Москва».

Справочник городов (`cities.py`) — ~64 тыс. городов от 5000 жителей из GeoNames
(https://www.geonames.org, лицензия CC BY 4.0) с зоной IANA, страной, регионом,
населением и названиями на английском и русском. Кроме них у города есть другие
названия — варианты написания, прежние, на других языках латиницей и кириллицей, — и
поиск идёт по всем («Питер», «Ленинград», «St. Petersburg» → Санкт-Петербург). Файл
`tma/backend/data/cities.tsv.gz` (2,8 МБ) собирает `scripts/build_cities.py` из выгрузок
GeoNames; в репозитории лежит готовый, пересобирать его нужно, только чтобы обновить
данные. Справочник загружается при старте API (около секунды, ~50 МБ памяти). Поиск —
по названиям, склеенным в одну строку (`str.find` вместо перебора), и занимает
миллисекунды; выше — совпадение названия целиком, потом начало названия, потом начало
слова в нём, а при равенстве — город крупнее. Последние слова запроса могут уточнять
страну или регион («портленд орегон»), а у одноимённых городов страны в списке виден
регион.

Без запроса экран выбора показывает каталог `GET /meta/timezones` — по поясу на зону
из `zone.tab` базы tz (pytz), с запада на восток. Город пояса — тот, что дал зоне имя
(для Europe/Moscow — Москва); он же показывается в настройках у тех, кто выбрал пояс
до появления справочника. Зоны без такого города в справочнике (острова, мелкие
города) подписаны по CLDR (библиотека Babel); оттуда же названия стран. CLDR хранит
часть городов под устаревшими именами зон (`Europe/Kiev` вместо `Europe/Kyiv`),
поэтому город ищется и по синонимам зоны. Смещения считаются на момент запроса — с
учётом летнего времени.

Раньше пояс выбирался смещением `UTC±N`; такие значения API по-прежнему принимает и
переводит в `Etc/GMT∓N` (`timezones.parse_utc_offset`; в именах `Etc/GMT` знак
инвертирован), а в настройках показывает как `UTC±N`. Пока пояс не выбран,
используется UTC.

### «Отмечать за вчера»
Режим сдвигает «сегодня» приложения на день назад: `services.user_today` возвращает
вчерашнюю дату, и от неё считается всё — какой день отмечает кнопка, запланирована ли
на него привычка, где кончаются история и серии. Отдельной логики для «вчера» нет,
поэтому фронтенд работает как обычно (оптимистичная отметка меняет последнюю ячейку
сетки). Отметки, поставленные за настоящее «сегодня» до включения режима, не видны до
завтра — тогда они станут вчерашними. Напоминания режим не меняет.

### Язык и тема
Язык интерфейса (`users.language`) и тема (`users.theme`: светлая, тёмная или
адаптивная) хранятся на сервере, как и остальные настройки, — и переходят вместе с
пользователем на другое устройство. Новому пользователю язык выбирается по языку его
Telegram; на этом же языке бот присылает напоминания.

Фронтенд держит все тексты на обоих языках (`strings.ts`) и раздаёт строки текущего
языка через контекст (`preferences.ts`). Ошибки API показываются не текстом сервера
(он на русском), а по коду ошибки — на языке интерфейса. Тёмная тема — те же
дизайн-токены с другими значениями (`:root[data-theme="dark"]`), поэтому компоненты
о темах не знают. Адаптивная тема следует за темой Telegram (`colorScheme`,
`themeChanged`), вне Telegram — за `prefers-color-scheme`. Чтобы язык и тема были
верными с первого кадра, последние значения запоминаются в `localStorage`.

### Repository pattern
Роутеры и сервисы не пишут SQL. Вся работа с БД — через методы `Repository`,
привязанного к одной async-сессии. Сессию на каждый запрос открывает зависимость
`get_repository` и коммитит её по завершении обработчика (откат при ошибке).

### Авторизация
Каждый запрос несёт `Authorization: tma <initData>`. Подпись проверяется при
**каждом** запросе по алгоритму Telegram Web Apps; дополнительно ограничен возраст
подписи (`TMA_AUTH_TTL_SECONDS`). Без валидной подписи — `401`.

## Обработка ошибок
- API отдаёт ошибки в едином формате `{"error": {"code", "message"}}` с осмысленным
  HTTP-статусом; непредвиденные исключения логируются, наружу уходит обезличенное
  сообщение.
- Бот логирует необработанные исключения глобальным `dp.errors`; сбой настройки
  меню при старте не мешает работе.
