# Архитектура StreakBot

Документ описывает ключевые архитектурные решения и причины, по которым они
приняты.

## Компоненты и поток данных

```
                 /start
Telegram ────────────────────► Бот (bot/) ──► приветствие + кнопка Mini App
   │
   │ кнопка «Открыть приложение» (web_app)
   ▼
Mini App (tma/frontend)
   │  HTTP, Authorization: tma <initData>
   ▼
API (tma/backend, FastAPI)
   │
get_current_user (проверка подписи initData)
   │
get_db_user (запись пользователя; создаётся при первом запросе)
   │
Router → Service (сборка привычек, отметка, настройки)
   │
Repository (CRUD)
   │
SQLAlchemy (async session)
   │
SQLite / PostgreSQL
```

Бот и API — два независимых процесса. Общее у них только `.env` и `BOT_TOKEN`:
бот им авторизуется в Telegram, API — проверяет подпись `initData`.

## Слои и ответственность

| Слой | Где | Отвечает за |
|---|---|---|
| Бот | `bot/*` | `/start`, кнопка Mini App в меню чата |
| Конфиг API | `tma/backend/config.py` | Загрузка и валидация `.env` (pydantic-settings) |
| Авторизация | `tma/backend/auth.py` | Проверка подписи `initData` (HMAC-SHA256) |
| Зависимости | `tma/backend/dependencies.py` | DI: сессия + репозиторий, пользователь Telegram, запись в БД |
| Роутеры | `tma/backend/routers/*` | HTTP-эндпоинты `/tasks`, `/settings`, `/meta` |
| Сервисы | `tma/backend/services.py` | История выполнения, переключение отметки, настройки |
| Валидация | `tma/backend/validation.py` | Проверка названия, частоты, часового пояса |
| Часовые пояса | `tma/backend/timezones.py` | Разбор `UTC±N` в зону IANA, подписи поясов |
| Репозиторий | `tma/backend/repository.py` | Единственная точка доступа к БД |
| Модели | `tma/backend/models.py` | ORM-схема (User, Task, TaskLog) |
| Миграции | `alembic/` | Версионирование схемы |

## Ключевые решения

### Бот — только точка входа
Вся работа с привычками идёт в Mini App, поэтому бот не хранит состояния и не
работает с базой данных: ни FSM, ни планировщика, ни middlewares. На `/start` он
присылает приветствие и inline-кнопку `web_app`; та же кнопка стоит в меню чата
(`MenuButtonWebApp`). Поэтому `TMA_URL` для бота обязателен.

- **Разметка через entities.** Жирные заголовок и призыв собираются через
  `aiogram.utils.formatting` (`Text`, `Bold`). Библиотека сама считает смещения
  entities (в UTF-16, с учётом эмодзи), поэтому тексты в `constants.py` хранятся в
  чистом виде, без экранирования и `parse_mode`.
- **Старое меню команд удаляется.** Список команд, зарегистрированный прежними
  версиями бота через `set_my_commands`, хранится на стороне Telegram. При старте
  бот вызывает `delete_my_commands`, чтобы пользователи не видели несуществующие
  команды.

### API — владелец данных
Модели, репозиторий и создание таблиц живут в `tma/backend`. При старте API
создаёт недостающие таблицы (`create_all`, существующие не меняет); схема
версионируется alembic.

### Регистрация пользователя при первом запросе
Отдельного онбординга нет. Зависимость `get_db_user` вызывает
`Repository.get_or_create_user` по данным из проверенной `initData`: при первом
открытии приложения запись создаётся, при последующих синхронизируются @username и
имя (если они не изменились, UPDATE не выполняется). Вставка обёрнута в SAVEPOINT:
если несколько первых запросов пришли параллельно и один уже создал запись,
остальные ловят `IntegrityError` и перечитывают её. FastAPI кеширует зависимости в
пределах запроса, поэтому `get_db_user` и обработчик маршрута работают с одним
репозиторием и одной сессией.

### Прогресс вычисляется, а не хранится
Отметки хранятся в `TaskLog` (одна запись на задачу и дату). История привычки —
182 булевых значения (сетка 7×26, старое → сегодня) — каждый раз собирается по
логам: день закрашен, если в эту дату есть лог со статусом `done`. Единственный
источник правды — журнал отметок, рассинхронизация исключена.

Приложение ставит только `pending` и `done` (переключение отметки за сегодня).
Статусы `skipped` и `missed` проставлял прежний бот; они оставлены в enum, чтобы
читались исторические записи, и в истории считаются невыполненными днями.

### Часовые пояса
«Сегодня» считается в поясе пользователя (`User.timezone`, строка IANA). Пояс
выбирается в настройках приложения как смещение `UTC±N` и переводится в
`Etc/GMT∓N` (`timezones.parse_utc_offset`; в именах `Etc/GMT` знак инвертирован).
Пока пояс не выбран, используется UTC.

### Repository pattern
Роутеры и сервисы не пишут SQL. Вся работа с БД — через методы `Repository`,
привязанного к одной async-сессии. Сессию на каждый запрос открывает зависимость
`get_repository` и коммитит её по завершении обработчика (откат при ошибке).

### Авторизация
Каждый запрос несёт `Authorization: tma <initData>`. Подпись проверяется при
**каждом** запросе по алгоритму Telegram Web Apps; дополнительно ограничен возраст
подписи (`TMA_AUTH_TTL_SECONDS`). Без валидной подписи — `401`.

## Обработка ошибок
- API отдаёт ошибки в едином формате `{"error": {"code", "message"}}` с осмысленным
  HTTP-статусом; непредвиденные исключения логируются, наружу уходит обезличенное
  сообщение.
- Бот логирует необработанные исключения глобальным `dp.errors`; сбой настройки
  меню при старте не мешает работе.
